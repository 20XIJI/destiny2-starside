# 后端与在线编辑台

管那支云函数与 `/admin/` 那一屏：访问计数、点赞、投稿、认证、角色、三张表、
就地编辑、审核台，以及本机与库之间的对账。
改 `functions/api/`、`admin/` 下任一文件、`tools/sync.py` 或 `tools/build-terms.py`
之前读这一份。

改发布链或云函数之前必跑 `npm test`。站点全局的机制与闸门在 `CLAUDE.md`。


站点只有一个后端：`functions/api/`，一支 Node 云函数挂在 CloudBase 的 HTTP 访问
服务上（`https://<envId>.service.tcloudbase.com/api`），管三件事：访问计数、配装
点赞、配装投稿。前端一律用裸 `fetch` 打它，**不引 CloudBase 的 JS SDK**：那份
runtime 比整站首屏还大。

接口地址只有 `shell.API` 一处定义。资料页由 `shell.foot()` 带上，配装页与填表页
由生成器写进产出（`convert-build.py` 的 `LIKE_JS` 与投稿按钮的 `data-api`）。
手写的首页 `index.html` 要跟着改，`check_shell.py` 的不变片段表里有 `shell.HIT`。

| 动作 | 请求 | 落在哪 |
|---|---|---|
| 访问计数 | `POST {a:"hit"}` | `counters/stat` 一条 doc：`pv` 累计、`d.<日>` 当日 |
| 读计数 | `GET ?a=stats` | 首页页脚那句「今日 X 位访客 · 累计 Y」 |
| 点赞 | `POST {a:"like",id,d}` / `GET ?a=likes` | `likes`，`_id` 是「赛季_slug」 |
| 投稿 | `POST {a:"sub",md}` | `subs`，`ok` 三档：0 待审、1 通过、-1 驳回 |
| 编辑台读写 | `POST {a:"docs"/"chg"/"pend"/"edits"/"emark"/"eds"…}` | 带 Bearer，见《在线编辑台》 |
| 本机对账 | `POST {a:"pull"/"push"/"list"/"mark"/"stat",k}` | 要 `ADMIN_TOKEN` |

本机那几个动作要 `k`，与云函数的 `ADMIN_TOKEN` 环境变量比对。
没配 ADMIN_TOKEN 就一概拒，不给「没设就放行」那条路。那等于把待审队列与
状态位开给所有人。编辑台那一串走 `Authorization: Bearer`，判权见下一节。

令牌只有 `.env.local` 一处（已 gitignore，样板见 `.env.example`）：
`cloudbaserc.json` 写 `{{env.ADMIN_TOKEN}}`，`tcb fn deploy` 读那个文件注进函数，
`tools/sync.py` 也从那里现读，不必 export。新机器上照 `.env.example` 填一份再
`tcb fn deploy api --force`。

envId 不进环境变量：它写在 `shell.API` 里、要落进每个页面的产出，本来就是
公开的，静态托管域名里就有它。

访问计数全部装在 `counters/stat` 这一条 doc 里：计费按数据库调用次数算，不按
记录条数，所以一次访问要写的那几个数（累计、当日、当日 UV）合在同一次 update 上，
`_.inc` 逐字段自增、原子且并发安全。页面级热度不自己存，看 CDN 控制台的 URL
排行。那是静态托管本来就在记的，免费。点赞一条一套：`_id` 即「赛季_slug」，字段
只有 `n`；先 update 再 set，doc 不存在时才多一次往返，首次并发写互相覆盖成 1，
掉几个数不值得上事务。

同一个浏览器每天只算一次，记的因此是访客数不是页面加载数。计数是写、挡不进
缓存，唯一能压的就是发的次数：一天一次，调用数与访客数持平，翻多少页都不再涨。
窗口写在 localStorage 的一个定长键上（`svd` 存天），不一天一个键。localStorage
不可用时去不了重，那台机器每次加载都算一次。落在计数窗口外、页面又没有
`<span id="sv">` 时一个请求都不发。

首页那句数字在浏览器里存十分钟：`svt` 存「取到时刻|文本」，过期再读一次
`?a=stats`。它按自己的时刻作废，不借 `svd` 判当天：`svd` 由当天先开的那一页写，
`svt` 只有首页写，先开别的页再进首页，读到的是几天前那一句。云函数里 `stats()`
按一分钟缓存在实例内存里，连日期一起记，过零点即作废。

赞数按五分钟缓存在函数实例的内存里：客户端那份缓存是每浏览器一小时、各存各的，
函数里这一份是所有访客共用一份，读调用因此与访客数脱钩。点赞写完不回读。新数就在
前端手里，自己加一即可，省一次调用，也不必等一个往返才看见自己那一下。

点赞去重只认 localStorage，换浏览器能再点一次。数只有运行时才知道，写不进
产出，所以生成器只出一个带 `data-like` 的空位，与资料页的当前时刻高亮同一条约定。
详情页给按钮，索引页只给数字：卡片整张是 `<a>`，里面套 `<button>` 不成立。

点赞与「复制配装」挂在标题那一行的右端（`.id-row` 里的 `.head-acts`）。它们是
对整套配装的操作，与标题同级；挂在推荐者下面时读者会以为赞的是那个人。复制的是
页面上那份 `<pre id="src" hidden>`：剥掉着色标记的源稿（`markup.uncolor()`），
粘回配装工具能直接导入，标记留着只会让人以为要照着写。站内没有第二处存它，所以
它落在页面上而不是另拉一个文件。

必需的这六项：名字、推荐人、职业、属性（分支）、类别、核心。缺了填表页就不让投。
半张稿子进了队列，审的人既补不出推荐人也猜不到核心，只能打回去，来回一趟。
装备与描述可以后补，这六项不行。两处写着这一组：`builds/new/form.js` 的 `NEED`
（挡投稿）与 `admin.js` 的 `NEED`（列缺失项）。

类别挡投稿，不进指纹。缺了 `convert-build.py` 当场中止、卡住整次构建，所以填表页
必须挡住；但它是站上的目录分法，改一次不该让审过一轮的稿子认不出自己那一份，与审核
意见同一条理由。云函数的 `SAME` 因此仍是五项，改类别不必跑 `rekey`。

同一套配装的判据就是那五项（名字、推荐人、职业、分支、核心），不按装备算。改一把枪
就成了另一套，而再投的人多半是想更新同一份。审核意见也不进这五项：它是站方后来加
上去的话，进了指纹会让审过一轮的稿子认不出自己那一份，而它一个字都不影响这是不是同一
套配装。重投分两路：

| 先前那一份 | 怎么办 |
|---|---|
| 还在待审 | 顶掉旧的，只审新的（同一 key 的待审只留一条） |
| 已经上站 | 这一次算**更新**：记下它的 `season`/`slug`，通过时沿用那两个覆盖过去 |

更新那一路不另开 slug：换一个 slug 等于站上多出一份重复的配装，点赞数也跟着
甩掉（点赞的 `_id` 就是「赛季_slug」）。通过时除了标状态，还把正文直接写进
`docs`。`sync.py` 的 `land()` 只写盘上没有的，已经在站上的那一份它不碰；写进 `docs`
之后走的是与资料页同一条对账路，库变了、盘没变，下一次 sync 自然拉下来。

换了 `SAME` 那一组字段之后要跑一次 `{a:"rekey",k:…}`：旧记录的 `key` 是按旧算法
存的，对不上就认不出「这一套已经上站了」。与 `sync.py --seed` 同一类，平时不用。

限流走 HTTP 网关的 `qpsPolicy`，不在函数里自己写：单 IP 5 QPS、总量 50。

### 在线编辑台

`/admin/` 是站内一个不链不收录的页面（`noindex`，不进 `shell.pages()`、不进搜索、
首页不给卡片）。编辑与审核都在线上做，落盘、构建与部署仍在本机：闸门是 Python，
搬不上云函数。

三个文件，手写，不进生成器：`admin/index.html`、`admin/admin.js`，以及生成物
`admin/terms.js`。样式走 `assets/site.css` 加一份 `admin/style.css`，后者只写站内
没有的那几件：登录框、块列表、源稿编辑器、闸门提示、对照视图。

#### 库是工作副本，git 是发布本

源稿在库里有一份 `docs` 集合，编辑台读写的是它；仓库里 `references/` 下那些 `.md`
才是发布本（`git ls-files references | wc -l` 即当前篇数）。
两边没有合并逻辑，只有覆盖，方向由 `tools/sync.py` 的**三方比**定：除了盘上与
库里两份，还在 `.git/starside-sync.json` 里记一份「上次对完账时每篇的 hash」当基线，
与 `refs/deploy` 同一个道理：它记的是这台机器对到哪儿了，不入库、不跨机器。

| 盘 | 库 | 做什么 |
|---|---|---|
| 变了 | 没变 | 推上去 |
| 没变 | 变了 | 拉下来 |
| 变了 | 变了 | 当场报出是哪几篇，一个字不动 |
| 删了 | 没人动 | 库里跟着删 |
| 删了 | 有人改过 | 算撞车 |
| 新加一篇 | 没有 | 推上去，库里没东西可丢 |

只比 hash 不记基线的话，「不同」永远推不出方向。那样一次推就会把线上刚通过的
改动静默覆盖掉，而它从来没落过盘，git 历史上一点痕迹都没有。批量改动与新增条目
在本地做更顺手，这条基线就是让那件事不必靠「改之前记得先拉」这种纪律。

撞车时把库里那份写在 `<路径>.md.remote` 旁边好逐字比（`references/` 走「全忽略 +
白名单」，`.remote` 不是 `.md`，不会入库），比过之后 `--mine` 或 `--theirs` 择一，
两者都顺手清掉那个 `.remote`。撞车那几篇的基线不动。记了下一轮就分不出方向。

`_id` 即源稿在 `references/` 下的相对路径去掉 `.md`（`docs/exotic-weapon`、
`artifact-mods`、`builds/s29-凯旋纪念碑/xxx-warlock`），换算只有 `id_of` / `path_of`
两处，后者用 `realpath` 挡穿越：`_id` 从库里来，而库是联网的那一侧。

日常一轮就是 `tools/ship.sh "提交信息"`，它按序跑这五步，任一步失败即停：

```
python3 tools/sync.py
npm run build
git add -A && git commit           # 工作区干净时跳过，也就不必给信息
python3 tools/deploy.py            # 末尾自动再对一次账
git push
```

末尾那趟对账拉回东西就报错退出：拉回来的源稿既不在这次的 commit 里，也没上站，
再跑一次 `ship.sh` 收掉。

#### 认证：裸 HTTP，不引 SDK

身份认证 v2 本身就是 HTTP 接口，`fetch` 直打
`https://<envId>.api.tcloudbasegateway.com`：`POST /auth/v1/signin` 带用户名密码
拿令牌，`POST /auth/v1/token` 用 `refresh_token` 换新的。**不引 `@cloudbase/js-sdk`**：
auth-only 入口 65 KB gzip、全量 136 KB，而整站首屏才 48 KB。

只有账号密码一条，没有自助注册。账号由管理员在云开发控制台的「用户管理」页
手工建，注册用户免费、不限量。网关默认策略对任何自注册的注册用户都放行云函数，
少一条注册入口就少一整类要挡的东西；十几个内部编辑者也用不着自助。

`access_token` 2 小时、`refresh_token` 30 天，都存 `localStorage`。被拒一次就拿
refresh 换一遍再打，重试只放一次：换完还被拒就是真的过期了，落回登录框。

网关那个身份认证开关不能开：它按路径生效，一开，`/api` 上的访问计数、点赞、
投稿全都要带凭证。校验放进函数自己做：拿到 `Authorization: Bearer` 就打一次
`GET /auth/v1/user/me` 换 uid，结果按令牌在函数实例内存里缓存五分钟，与
`likeMap()` 缓存赞数同一套写法，这次往返因此与请求数脱钩。**不自己解 JWT 验签**：
要拿 JWKS、要处理轮换，换不出东西。

登录成功 ≠ 是编辑者。网关默认策略对任何自注册的注册用户都放行云函数，所以
身份由认证服务给，权限由 `editors` 这张白名单给，缺一条都不行。账号怎么来的不影响
系统：控制台手工建注册用户（免费、不限量）也行，本人自注册也行；没进白名单的人
登录后页面上写着自己的 uid，管理员照着加一行。**不走组织成员**：那条按人头收费，
换来的隔离粒度这个场景用不上。

#### 角色是一个整数

`editors` 里的 `lv`：1 编辑、2 审核员、3 管理员、4 超管。判权是一次 `>=`，
不建权限矩阵。整张 `editors` 表归超管：看名单与改名单是同一层的事，`LEVEL.eds`
与审核台那枚标签同一个门槛，不靠前端藏。

| 动作 | 门槛 |
|---|---|
| 读源稿、存草稿、提交待审 | `lv >= 1` |
| 通过 / 驳回（文档改动与配装投稿） | `lv >= 2` |
| 看编辑者名单、加人、改名、改角色、移除 | `lv >= 4`，且只能动 `lv` 严格低于自己的人 |
| 落盘、构建、部署 | 不在线上，只在本机 |

每个动作的门槛只有 `functions/api/index.js` 的 `LEVEL` 一张表，`route()` 进分支前
判一次；分支体只留业务，不再各自 `await who(event, N)`。表里 `null` 是公开（连令牌
都不要），数字是 `who()` 的门槛，`'admin'` 走 `ADMIN_TOKEN`。新增一个动作忘了在表里
写门槛，`npm test` 当场报——那一条按表遍历，断言每个非公开动作无凭据时都被拒。

改名与加人是同一个动作（`op:'set'` 对已存在的 uid 走 `update`），编辑者那一屏的行内
给一枚「改名」，级别原样带回去——那个动作一次写整条，不带 `lv` 会被当成「改成 undefined」
挡下来。**改的只是这张白名单**：记录里的 `by`/`okBy` 是当时那个名字的副本，改完不回溯，
旧记录照旧写着旧名字。

最后一行那半句一句话钉住两件事：管理员动不了超管，也造不出第二个超管。
**不做范围权限**（某人只能改配装、不能改资料页），`lv` 一维。

`.env.local` 里那个 `ADMIN_TOKEN` 解析成 **`lv 5`**，压在四级之上，兼作破窗钥匙：
`sync.py` 用它，第一个超管也靠它进管理页加进库。必须高于 4：判权那条是「只能动
`lv` 严格低于自己的」，破窗若也是 4 就造不出超管，引导整个走不通。移除一个人就是删行，不设停用位。记录里
存的 `by`/`okBy` 是名字字符串不是引用，删了不会让历史悬空。

#### 三张表

```
docs     { _id, md, at, by, hash, landed }                一篇一条，源稿的工作副本
edits    { _id, doc, blk, cell, before, after, by, uid, at, ok, okBy }
editors  { _id: uid, name, lv, at }
```

`docs` 的 `landed` 是**上次对完账时那一版的 hash**，只有 `tools/sync.py` 写得动它
（`push` 顺手写，别的篇由 `sync()` 末尾补）。`hash != landed` 即「线上改过、还没落盘」，
审核台据此把那一套摆进「通过」档。**判据挂在内容上，不挂在动作上**：存一位「改过了」
的话，改一版又改回原样就永远清不掉——三方比看到两边都没变，什么都不做。
线上的编辑一律不碰它，`smark` 更新已上站那一套时只写 `hash`。`landed` 为空即视为已落盘。

**并档只并在筛选与计数上，`state` 本身不动**：`subDetail()` 的保存、申请移除、撤回
三枚按钮都按 `state` 分路——把 `live` 换成 `pass`，保存就写去 `subs`（改动落不了盘）、
申请移除整个消失、撤回换成一枚后端必拒的死按钮。并档由 `bucket()` 一处做。

`docs` 列表按前缀分两半投影：配装那些带 `md`，资料页那些不带。投影是为资料页
存在的（38 篇合计 1.5 MB）；配装 35 套合计 65 KB，而编辑台的列表要靠 `md` 读出名字、
职业、分支、类别与推荐人。35 套里有 20 套是本机直接落盘的，`subs` 里没有对应的
投稿记录，不带 `md` 的话它们在列表上连名字都只剩一个 slug，更挂不到类别／职业那棵树上。

一处改动一条记录，不是一份文稿。`blk` 是源稿行号、`cell` 是格号（`-1` 即整块，
段落、列表项与表格整行都走它；用 `-1` 不用 `null` 是因为那一列要参与 `where` 查询），
`before`/`after` 是那一处的原文与新文。同一个人在同一处只留一条待审，重改即改写。

整批成功后就地结案，失败才整装核实。`mark()` 将二元数组转换为
`{a:"emark",jobs:[{id,ok},…]}`，一次请求提交整批。成功后更新 `S.edits` 和 `badges()`，
再发一遍 `pend` 重判本页剩余提案。冲突或网络结果不明时保留本地状态、重拉队列核实，
不自动重发；忙碌期间禁用本页审核按钮并显示回执。

结案不清内容：`before`/`after` 各是一格，留着就是历史，「改动记录」那一页看的
就是它。同篇其余待审也不再整批驳回：它们改的是别处，与这一处无关；存整篇快照
时「同一篇有两份待审」天然互斥，那时通过一份就得把别人那一处连内容一起抹掉。

全站只有一种编辑方式：三个资料生成器都戴了 `data-b`，整篇快照那条路（`put`）
与块列表编辑器一起删掉了。早先那批快照形状的已结案记录仍留在库里，`histOne()` 按
记录有没有 `after` 分两支读。

`edits` 的 `ok`：0 待审、1 通过、-1 驳回。没有草稿。要改就当场改完再提。

定位先按 `before` 原文匹配，`blk`/`cell` 只当同一文本出现多处时的消歧。
提交时验一次、通过时再验一次：那一处的原文已经不是原样了，提交回 `stale`、
通过回 `conflict`，记录原样留着：`before`/`after` 都还在，审的人看得见两边
分别要改成什么，提的人也找得回自己写了什么。

表格那一行里的回车就地并成 `\\`，两处都做。编辑框里按回车直接插 `\\`、粘进来的
多行也就地并掉（`edit.js`），云函数收改动与通过改动时再各并一道（`chg` 与 `emark`，
判据是那一行以 `|` 开头）。**不拒收，直接改对**：「格内换行写两个反斜杠」这条只写在
源稿语法里，编辑的人没有理由知道；而混进一个真换行，那一行写回正文时裂成两行、格数
少一半，`npm run build` 当场中止，卡住的是整次部署，编辑那一侧却一点异样都看不到。

先信块号会静默改错格：读者看到的页面是上次部署的产物，库里通过的改动往前
插了一个块之后，块号整体偏移，而原文不会。同一条规则管两处：页面上 DOM 反查源稿，
以及审核时在当前正文里定位。
页面 hash 与库不同的时候，`edit.js` 只接受原 DOM 文本在当前源稿里的唯一匹配；
表格限定同一列，多行块必须完整同跨度。重复文本、纯图标、内容已变或不支持的结构
不按旧行号猜，提示等待新版页面后重新提交。涂色与本人待审续写也核对原 DOM，
不会把涂色后的新旧拼接内容当底稿。

通过即把那一处替换进 `docs` 的正文，只换那一格、不重拼整行。整行重拼会让改一个
字的提交在 git diff 上标红一整行；写回按 `cellSpans()` 给的区间替换，两侧的空格
原样留着。

权限不足回 `no permission`，令牌失效才回 `forbidden`。两件事共用一个词时，前端会
把权限不足也当成令牌过期去换一张再打，`lv` 不够的人点一下白跑三趟，报出来的话还看不出
是权限问题。

#### 就地编辑

登录之后在任意资料页上直接点、直接改，不必先去 `/admin/`。这条路在这个仓库
成立的理由很具体：`convert-doc.py` 的逐字保真闸门保证产出剥掉标签后与源稿逐字相等，
所以页面上任何一段可见文本都能反查回源稿；而属性不进保真比对，生成器可以给块
戳定位标记，闸门一个字不用改。

引子在 `shell.EDIT`，有令牌、且这一页带 `main[data-src]` 才拉 `admin/edit.js`，
没登录的读者只多下这一行。判据要连 `data-src` 一起看：只看令牌的话，填表页、
索引页与首页也会各下一份 `edit.js`，而它们改不动任何源稿，`edit.js` 进去第一件事
就是 return；编辑台把填表页当 iframe 载进来，那 20 KB 因此每换一条配装白下一次。
相对前缀从 `site.css` 那个 `<link>` 上现取：页面深浅不一，写死 `../` 会在
`elements/arc/` 这种两层的页面上指错；站内绝对路径又会在 `file://` 下指到磁盘根目录。
它与 `HIT` 分成两段：那个 IIFE 里有 early return，接在后面会被跳过。
手写的首页 `index.html` 要跟着改，`check_shell.py` 的不变片段表里有 `shell.EDIT`。

三个资料生成器都戴标记：`convert-doc`、`convert-artifact-mods`、`convert-armor-sets`。

配装详情页也戴 `data-src`，但走另一条路，由 `<main>` 上的 `data-kind` 分：资料页
`doc` 逐格改，配装页 `build` 整篇替换。配装页没有 `data-b`，逐字保真闸门也不覆盖它，
逐格无从落脚也无从校验，所以那一枚「编辑」开的是一层铺满视口的遮罩，里面按
`isSet()` 载单套或合集填表页，保存走 `bsave`——与审核台详情格里那一套是同一个动作、
同一个落点，不新开状态流。`isSet` 从 `admin.js` 的导出拿，不在 `edit.js` 里抄第二份：
它与 `convert-build.py` 的 `split_set()` 必须逐字一致。

底稿走 `pend` 带 `md` 那一路现拉，**不拿页面上那份 `<pre id="src">`**：它是
`markup.uncolor()` 剥过着色标记的，存回去会把整套配装的着色洗掉。保存的回执要写明
「这一页要等本机落盘、构建再部署才更新」——页面是构建产物，存完一个字都不会变。

**索引页与填表页一律不戴 `data-src`**：填表页被编辑台当 iframe 载进来，戴上就是每换
一条配装白下一次 `edit.js`。

开编辑态只等一发。从前是四个串行往返：`terms.js` → `admin.js` → `doc` → `pend`。
两头各去掉一段：

1. 词表现读，不在模块顶层捕获。`admin.js` 从前一进来就把 `window.starsideTerms`
   存进 `T`，`terms.js` 因此必须先执行，两份脚本只能串行注入。改成 `lint()` 里现读之后
   顺序约束消失：`toggle()` 只注入 `admin.js`，104 KB 的词表进编辑态之后空闲预取，
   点开某一块时若还没到就等它一次，到了再把调色板与闸门提示补上。预览不等它。
   `paint()` 只认花括号、不查词表，所以改完当场就看得见渲染的样子。
   同一条也让 `/admin/` 那一屏不必再引 `terms.js`：`lint()` 全仓只有 `edit.js` 一个
   调用点，编辑台自己从不跑闸门，那 20.5 KB gz 是白下的，`.js` 只有 5 分钟浏览器缓存。
2. `doc` 与 `pend` 合成一发。`pend` 带 `md` 时把这一篇的正文与 hash 一并带回，
   `stale` 由服务端比 `hash` 自己判。它本来就要读一次 `docs`（`judge` 那一路拿正文跑
   `locate`），多带两个字段不多一次查询。

定位标记戳在块级元素上（`<tr>` `<p>` `<li>` `<dt>` `<dd>` `<h2>` `<h4>`），`data-b`
的值是源稿行号，多行的段落写成区间。`<main data-src="docs/<slug>" data-hash="…">`：
`data-src` 是这一篇在库里的 `_id`（产出目录 `elements/arc` 与源稿路径 `docs/arc` 不是
同一个），`data-hash` 是构建时那份源稿的 sha1，与库里 `docs` 那一条的 `hash` 同一个
算法，要在 `land()` 改写链接之前算。

部署空窗现算，不存状态。`edits` 仍只有 0/1/-1 三档，没有「已上站」那一档。通过
之后那一处就该像没标记过一样，存一位状态会随迭代积出一堆陈旧标记。判法是：
`data-hash` 与库里的 `hash` 相等就没有待上站的改动，一处都不必比；不等才把该篇
`ok=1` 的记录取回来（`pend` 带 `stale`），判据是页面上这一格显示的正是它的 `before`。
库里早就是 `after` 了，拿库里比永远相等。

`data-b` 落盘前改写成增量（`markup.delta_bmarks`，在 `shell.emit()` 一处，四个
生成器共用那个出口）。文档顺序里行号单调递增，绝对值是一串互不相同的四位数、gzip
压不动，差值多在个位数且大量重复：神器模组页因此从 +13.0% 降到 +2.7%，护甲套装页从
+10.7% 降到 +2.8%，全站 +1.3%。区间写成「差+跨度」。解码在 `edit.js` 的 `decode()`，
按文档顺序累加。倒退即中止：那说明产出顺序与源稿行号的顺序对不上了，解码会静默
指错块，而页面上看不出来。

`vocab.py` 捕获说明片段时要剥掉 `data-b`：它是反查源稿用的行号，落进
`builds/desc.js` 的悬停面板里没有用处，只会让那份文件白涨一截。

格号不落进 HTML，用 DOM 的 `cellIndex` 现取：4339 行表格约三万五千格，逐格戳要
多出几十 KB。合并行没有 `<th scope="row">`，`cellIndex` 整体前移一位，源稿格号
= `cellIndex + 1`，判据与列组隐藏那两条规则同源。

连号就不戳：一张表的行在源稿里本来连着，413 行的表逐行戳一遍要多一千多字节
gzip。省掉的那些由「没有 `data-b` 的 `<tr>` 就是上一行 +1」补回来，而生成器只在
这条成立时才省。表头那一行必戳，所以每张表的第一个 `<tr>` 必然带号，这条规则不会
跨表接到上一张去；行组分界行（`|---|`）占一行却不出 `<tr>`，它后面那行也照旧带号。
全站合计 +0.87% gzip。

切格规则只有两份实现：Python 的 `markup.cells()`，JS 的 `admin/dialect.js`。
跨语言没法共用源码，两份是下限。JS 那一侧由 `admin.js`、`edit.js` 与云函数共用同一个
文件；云函数只 `require` 得到自己目录下的东西，所以 `functions/api/dialect.js` 是
构建复制过去的，**不手改**，两份逐字相同由 `npm test` 钉住。

五处曾有分歧的地方各选定了一种，判据写在 `dialect.js` 的注释里：只有 `{token|` 才
开一层，深度钳在 0，行首不许有空白（直接返回 `null`，不先 trim），只剥半角空格，
首尾各去一个 `|`。选定的这一种与合并前的实现在全部 4563 行语料上结果逐字相同。

`check_quality.py` 的 `CellSplitting` 拿全部真表格行断言「源稿还落在两份都认的形状
里」；`check_quality.cjs` 管 JS 那一份自己的行为，以及「没有哪个消费方又抄了一份
回去」。

产出里的裸标签正则会被标记打断。`vocab.py` 三处写着 `<tr>`、一处写着 `<h4>`，
戴上 `data-b` 之后一条都匹配不上，带 `data-band` 的合并表其实早就匹配不上了。
新加标记之后要扫一遍还有没有别处按裸标签认产出。

涂色两档，17% alpha：待审琥珀 `#ffbb48`、已通过待上站青 `#4fd6e0`，写在
`admin/edit.css` 的 `--se-*`。`edit.js` 的 `shade()` 只按 `ok` 分这两态，
页面遮罩上没有冲突那一档：冲突要靠 `pend` 带回的 `judge` 才判得准，
那一路只落在审核台（`admin/style.css` 的 `.pane.bad`）。**不挂 `--accent`**：它逐页被覆盖成
六种元素色（护甲模组页金、增益减益页紫、配装页按分支），而遮罩是站点工具，得在
三十个页面上长一个样。八档色阶染的是文字不是格子底，背景这条通道让得出来。
避开红与绿：红撞 `--c-health` 且与洋红 ΔE 6.9，绿与青 ΔE 11.3，两对都视作同色。

新值换进原位，旧值紧随其后，两半都是渲染态。一边源稿一边成品看不出改了什么。
新值由 `edit.js` 的 `show()` 近似渲染（`paint()` 加格内换行、图标、链接、粗体四样），
旧值直接用页面上原本那一份，它是生成器渲染的，忠实。表格里落成下一行：列宽被
14 个页面的 `table-layout: fixed` 加写死的像素值钉住，左右并排会把两半各压成半列宽。

旧值保留自己的着色、整体压暗，不刷成中性灰：改一个 token 的着色时两半都带色
才比得出来。**不写「原为」二字**，划掉那一道已经说完了；谁改的与什么状态走格子的
`title`：一页改十处时，十个名字排在正文里是噪声。

涂色那两条必须 `!important`。格子的底色由 `.gen tbody tr[data-band="1"] > td`
这类 (0,3,1) 的选择器给，单类的 `.se-hit` 只有 (0,1,0)，压不过；`boss-hp` 的 61 处
合并行全带 `data-band`，不加就静默不显形。与 `site.css` 里 `[hidden]` 那条同一类
问题：遮罩要盖住的是各页各样的规则，不加就得逐页重述一遍。

小框里给实时预览：`{res|90% 减伤}` 少一个花括号、token 写错一个字母，在源稿里
眼睛查不出来，渲染一遍当场就露。闸门有错时把提交按钮上的字换掉（「有 N 处问题，
仍要提交」），提示不拦截，真闸门是本机那套 Python。

#### 审核台：资料页树 + 逐处审核

四个标签：配装 N / 文档 N / 记录 / 编辑者。配装与文档分开：两种东西的形状与
操作都不同，挤在一个队列里只能各挑各的。配装排在最前，登录后也落在它那一屏。
站上多数改动从那条队列来。落地那一屏在四处写着同一个值：`draw()` 的缺省、
起手那一格的 `replaceState`、`boot()` 末尾那一句，以及 HTML 里 `aria-current` 挂在
哪一枚 chip 上。四处要一起改：只改前三处，第一枚 chip 就不是亮着的那一枚。

左栏是资料页树，不是文件路径。读者看到的是一个个资料页，`docs/boss-hp` 这种
路径只有写源稿的人认得。树由 `admin/pages.js` 给（`build-terms.py` 生成），从三处
现成数据拼出来，各管一段：

| 出处 | 管什么 |
|---|---|
| 首页 `index.html` 的 `.group-label` | 有哪几个大组，每组下又有哪几张卡 |
| 源稿的「路径：」 | `elements/<x>` 那 7 篇挂在职业分支详解下 |
| 源稿的「卡片：」 | `pve-farming` 列出的那几篇挂在它下面 |

两处嵌套的出处不同不是疏漏：职业分支详解那一族真的嵌在文件系统里，刷取指南
列的那几篇在站点根下、只是逻辑上属于它。硬要统一成一种就得改其中一页的渲染。挂不上任何
一处的（配色总览）落到「站务」。一行六列：`[_id, 标题, 页面路径, 分组, 父页, 更新]`。

树只列有东西的那些分支，为 0 的页面连同空掉的父页与分组一起不出现：一屏全是零
会把真有待审的那几页淹掉。右栏一次列出该页的全部待审，各带发起者与逐处的通过／驳回，
外加一枚「这一页全通过」和一条「去看这一页」。

改动记录以时间为主轴，每条写「档案 › 首领生命值 · 第 40 行第 8 格 · 日栎w → 剑崎」。
左栏同一棵树在这里当筛选器，点一页只看那一页，再点一次取消。记录答的是「最近发生了
什么」，按页分树会把时间打散。

#### 一键通过与两类冲突

有冲突就一条都不落地，先让人把冲突组挑完再整体走一遍，不是「能过的先过掉」。

| | 怎么发生 | 挑什么 |
|---|---|---|
| 甲 · 同一处多份 | 两个人都改了同一行同一格 | 两份都基于同一版正文，挑哪份都落得下去 |
| 乙 · 底稿动过了 | 那一处的 `before` 在库里已经找不到（他提交之后、审之前，别人改同一格那条先通过了） | 候选里多一个「保持库里现状」，选它即全部驳回 |

甲类前端分个组就看得出来（按 `(行, 格)` 归堆），乙类只有拿 `locate` 对着当前正文
跑一遍才知道，所以 `pend` 带 `judge` 时由后端顺带判一次并标上 `stale`：那个判断只有
`locate` 做得准，**不在前端再抄第四份切格与匹配**。

陈旧提案不重设底稿、不猜位置。保留原文与新文对照、驳回和保持现状，通过禁用。
提示「底稿已变，请回资料页重新提交」；页面还没部署新版时必须等待，刷新旧 HTML
不能解决。审核台不再按旧行号读一格、生成替代提案。

结案以整批为原子边界：单条也是一项 jobs，旧 `id/ok` 请求拒绝。云函数使用
`db.runTransaction(callback, 0)`，冲突不自动重试。先按原始正文定位所有通过提案，
拒绝重叠，再从后往前替换，每篇只写一次；正文与所有状态一起提交或回滚。
N 条提案、D 篇通过文档须满足 `N <= 49` 且 `2*N + 2*D + 2 <= 100`，不拆批部分提交；
审核台一页超过 48 条时禁用全部通过。云函数与审核台必须一起发布，旧缓存需刷新。

#### 前端闸门是提示，不是拦截

`admin/terms.js` 由 `tools/build-terms.py` 从现有的唯一真相导出，不另立词表：
`check_terms.TERMS`（G1 正名、G2 token 唯一）、`check_terms.tint_classes`
（G3 token 有定义，同时是芯片的调色板）、`items.load()`（G6 正查）。改一处两边同时
生效。芯片那一份再用 `check_tokens()` 返回的 `used` 收一道，与 G7 的色板页同一条
判据：不收时 50 枚里有 18 枚是外壳与组件的类（`wordmark`、`site-foot`、`entry-stamp`、
`tool-search`…），全站源稿里一次都没出现过，点一下只会生成一个不该有的标记。
收完剩 32 枚。一条记录一行，与 `assets/search.js` 同理，按行写让 git 存得下增量。

浏览器里另加两条本地闸门查不到的：花括号闭合，以及表格行的格数与表头一致。
切格要记花括号深度，`{ico|…}` 内部也有竖线。

三处照 Python 那一侧原样搬，少一条就满屏误报：

1. G6 的六处跳过（`items.hits_in()`）：键行与标题行、表格里行标题那一格、链接目标、
   `GUARD` 里更长的专名、已经在某个标记里的、表头行。表头行要跨块判：块是一行
   一个，分隔行落在下一块里，在块内看下一行永远判不出来，32 处列名曾因此被要求着色。
2. G3 按页判：站内每页再叠一层自己的样式表，`{ico|…}` 只在 `ability-cooldown` 有。
   只按 `site.css` 判会把九千多处整批报成没定义。`terms.js` 只存相对 `site.css` 的增量。
3. G1 的 `KEEP` 白名单：`Destiny 2: Boss Damage` 这类官方专名整条放行，链接目标同理。

「该着色」那类提示只在编辑那一块时列出来，闭合的块只显示错误：一屏都挂着的话，
错误就淹没在提示里了。

等价关系由断言页钉住：`npm run build` 过得去的源稿，前端闸门必须零错零提示。

跑不动的留在本地：逐字保真、神器模组三个一组、每套 2 件 + 4 件、分节计数。
一篇改坏会让 `npm run build` 中止、卡住整次部署，办法是 `git checkout` 那一篇再回
库里驳回，**不为此在线上造第二套校验**。

#### 配装投稿

载进来的是可以改的填表页，不是一张只读的图。`builds/new/index.html` 本身就是
浏览器里的配装编辑器，`iframe` 载进来调 `window.starsideForm.load(md)` 即可；
装备写错、描述要润色，审的人改完再通过比打回去让人重投快得多。通过时用
`starsideForm.read()` 现读那一份带给 `smark`，落盘的是它，不是投的那一份。

**不替他按「预览配装」**：预览态下 `#sheet.preview` 把输入框与格子全设成
`pointer-events: none`，整页点不动，那就成了一张假表。那一页右下角自己带着这枚按钮，
想看成品点它即可。但「投稿」按钮要摘掉（`#send`），它在审核页里按一下就是再投一份。

赛季与 slug 不让人填：赛季就是当前这一季，slug 是「八位随机串-职业」（职业从
源稿的 `职业：` 行现读），两者前端现算。审的人多数时候不想在这里停下来想名字，而
这两样从源稿里推得出来。形状与查重照旧验在云函数：`^[a-z0-9][a-z0-9-]*$`、赛季
形如 `s29-…`、已通过的投稿与库里已有的源稿都不许撞；撞了当场拒，前端换一个随机串
再来。更新那一路跳过查重：「已经存在」正是它要覆盖的那一份。

整批清空一次删完（`subs.where({ok:-1}).remove()`），不逐条 remove：33 条废稿逐条
就是 33 次串行往返、33 次计费调用。

已驳回的可以真删（`sdrop`）：单条 `lv >= 2`，**不带 id 的整批清空要 `lv >= 4`**。
一次抹掉几十条，手滑的代价与逐条不是一个量级。去重从不查 `ok=-1` 那一档：
`sub` 只在待审与已通过里找同一个 key，所以删掉废稿不会让它被当成新投稿重新收进来。
按装备算指纹的那一版不能删：那时重投的判据要靠旧记录认。

删一套已上站的配装走审核，不当场删（`bdrop`）：站上少一页、点赞数也跟着没了，
按错一下没有退路。落成一条 `drop: 1` 的待审记录，与投稿走同一条队列、同一套通过与
驳回；同一套只留一条待审的申请，重复点即改写。它自成一行、不认领那一套：站上
那一篇还在（要等本机 sync 才真的删），两行并排摆着才看得出「这一套在站上，同时有人
申请删它」。

删除本身在本机：`sync.py` 每轮只读一次投稿列表，`sweep()` 先比本地稿与同步基线。
本地有改动或缺少基线时保留文件与基线，报「删除与本地修改冲突」，该目标不再参与普通
推拉，也不由旧通过投稿恢复。`--mine` 先驳回该目标全部已通过删除申请，再推本地稿；
`--theirs` 明确接受删除。无冲突删除先清远端、成功后才 unlink 本地并清基线。
远端失败不删本地；本地删除失败明确报告部分状态，重跑不猜，仍按三方比报冲突。
「库里没了就删盘上的」那条路不走，删除必须有通过的申请。

普通投稿的查询排除 `drop:1`（兼容旧记录没有 drop 字段），新投稿写 `drop:0`；
覆盖待审还要同时核对 id、key、ok 与类型，失败回 conflict。删除快照不能被保存或带 md 审核。

全量配装生成成功后，按所有赛季源稿清掉无源稿的详情 `index.html`，不碰符号链接、
目录与未知资产。单 slug、失败、空源稿不清理；旧赛季有源稿的页面保留。
最后一份当前赛季合集移除时删旧合集索引，首页残卡由现有成对闸门报错，手工撤卡后重跑。

列表列到类别（强度／创意／PVP）：它答的是「这套为什么被推荐」，与旁边说「在队伍里
干什么」的定位不是一回事，走 `--c-legend`。

改动记录点一条就地展开，不跳走。跳到单独一屏会把左栏那棵树与滚到哪儿一起丢掉。
一次只开一条：同时摊开几条 diff，行与行就对不上了。

左栏是类别 → 职业两级树，与站上索引页的分节逐层同形（那一页也是类别大节、职业
小节）。只列有东西的那些分支，与资料页树同一条规矩。三张词表（职业、类别、分支）
由 `admin/pages.js` 给，`build-terms.py` 照 `markup.py` 那一份导，不在 `admin.js` 里
另抄一遍，加一个分支或类别只改那一处。状态四档另走一维，留在右栏顶部当 chip，
保持多选；树上的计数跟着它走，只看待审时树上数的就是待审。

行的左缘那条 2px 亮边恒亮，颜色走该套配装的分支色，与站上索引页每张卡的左缘同一
条规则。行式不是卡片式：一屏要扫六七十条，卡片得滚三屏，而卡上没地方写「待审 / 已驳回 /
缺推荐人」这些审核才需要的东西。

详情摊在列表下面，不跳走，与「改动记录点一条就地展开」同一条约定。跳到单独一屏会把
左栏那棵树与滚到哪儿一起丢掉，所以点一条由 `buildDetail()` 把 `#stage` 滚进视野。
列表攒到几十条时那一格在两千像素之下。让位量按 `.site-head` 实测现算，写进那一格的
`scrollMarginTop`，不吃 `--stick`：那个变量由 `app.js` 写回，而编辑台不引 `app.js`，
`site.css` 里 45px 的缺省值比这一页的站头（89px，多一条标签栏）矮 44px，照它滚过去
「← 收起」正好压在站头底下。只滚点击这一条路：`subDetail()` 每次重画都会跑，
筛选与 popstate 回来时跟着跳就成了乱窜。收起不必自己滚回去：`history.back()`
把滚动位置恢复到按下那一刻，实测回到原处。

那一格的骨架固定在 `admin/index.html` 里：头 / iframe / 脚三块，只有头与脚清空重建。
iframe 一旦被 append 进重建过的容器就是重新挂载，浏览器照规范把整页再载一遍，而填表页要
`site.css`、`builds/style.css`、`vocab.js` 与 `form.js`，换一条配装就重付一次解析与
布局。换页时由 `show()` 把它收起来，只收 DOM 不动 `openBuild`：`buildsView` 自己
也走 `show()`，清掉状态它就再也画不开那一格了。

头分左右两列，动作排在右上角：左列收起与铭牌，右列保存／通过／驳回，`tip` 那句回执
跟着按钮走。iframe 有 86vh，动作留在它底下就离刚点的那一行一整屏，报错也报在看不见的
地方。脚只装《原文》：它是参考材料不是动作，且展开时 `pre` 有 `max-height: 50vh`，
摆在上面会把 iframe 整体顶下去半屏。**不给头吸顶**：站头 56px 加头那一块约 60px 加
86vh，滚到位之后按钮整程在屏内。

通过那枚走 `.go`，着 `--c-strand`，与列表上【通过】那枚状态标（`.rows .flag.pass`）
同色。角标要一并点亮（`::before` / `::after` 的 `opacity: 1`）：`.chip` 的 `border`
是 0，形状全靠那两枚 L，静置时透明，只改颜色的话一排按钮仍旧长得一样。**不用
`--accent`**：在 `.acts` 里它已经占了「当前选中」，拿来标通过会读成这枚被选中了。

配装那一页管所有配装，不只是待审投稿。已上站那些的在线入口只有这里：配装页没有
`data-b`，资料页那套逐处编辑在它们身上无从落脚，改法本来就是填表页整篇替换。四个
动作分工明确：**保存**（存一版，状态不动；已上站的走 `bsave` 写回 `docs`，待审的走
`ssave` 写回投稿记录）、**通过**（发布存过的那一份）、**驳回**、**撤回**。

通过与驳回都退得回待审（`smark` 发 `ok: 0`），所以这两枚都不问一声。通过那一档只在
落盘之前退得回：上了站之后盘上有源稿、站上有页面、点赞也挂上了 `_id`，只退库里的状态
会让两侧对不上且无人报出，那时要撤只有「申请移除」。驳回那一档不受这一条管——它从来
没落过盘，哪怕记录带着已上站那一套的 `season`/`slug`（`updates` 那一路）也照样退得回。
撤回驳回之前查一次同 `key` 的待审：投稿人已经再投了一份时当场拒（「已有新的待审投稿」），
不然同一套会在队列里留两条，两条都通过就在站上多出一份重复配装。

默认只开「待审」那一档：一进来就该是待办清单，另外三档按需打开：74 条里 33 条是
废稿，全列出来会把待审那几条埋掉。状态词一档一个词，不写解释：待审、通过（审过了
还没落盘）、完成（站上已经有了）、待移除、驳回。

已上站又被 `bsave` 改过的那些落进「通过」档——那一档答的就是「这一轮 sync 要发什么」，
两种来源同属一档。**档不多开一个，词分得开**：行上标「已改」不标「通过」，筛选与树上
的计数照旧按五档走。本机直接落盘、`subs` 里没有投稿记录的那 20 套同理，判据只挂
`docs` 上，那一支自然覆盖到。

谁经手的记在三处，铭牌第二行读它们：`subs.okBy` 是通过／驳回／撤回的人（一条只留
最后一个，与 `edits` 那一侧一致），`subs.edBy` 是待审时在填表页里改过的人，
`docs.by` 是已上站之后改过的人（`smark` 更新那一路写通过的人，**不写「投稿更新」这类
状态词**：一个词摆在人名的位置上读起来像有个人叫这个名字，这一版是不是投稿更新来的
由 `sub.updates` 答）。**`edBy` 不能只认 `ssave`**：审的人多半改完直接点通过，
`smark` 那一路把填表页现读的正文带过来，与库里那份比一下就知道动没动，`cur` 本来就要读。
「改」取哪一份看这一套在哪一段：`hash != landed` 时取 `docs.by`，否则取 `subs.edBy`
——没改过时 `docs.by` 是 `sync.py` 写的「本机」，写出来没有信息。

在线只标状态，写盘只在本机：`sync.py` 的 `land()` 把库里标了 `ok=1` 且带着
season 与 slug、而盘上还没有的那些写成 `references/builds/<season>/<slug>.md`。
只写盘上没有的：重跑一次不该把已经改过的源稿按投稿原文盖回去。

#### 离线断言

`paint` / `lint` / `cells` 三条纯函数不碰 DOM，`admin.js` 末尾按 `module.exports` 与
`window.starsideAdmin` 各导一份，`edit.js` 直接用那一份，**不复制副本**。

四条断言从仓库里那几份现取，写在 scratchpad：

1. `data-b` 指的行对得上：产出里每个带号的块，文本按保真那套归一化之后与源稿
   对应行逐字相等。这一条连「没有 `data-b` 的 `<tr>` 就是上一行 +1」一起验了。
2. 切格：`markup.cells()` 与 `admin/dialect.js` 拿全部真表格行对。
3. `locate()` / `patch()`：改一格只动那一行、邻格不动、两侧空格原样留着；
   原文对不上即冲突；同一文本多处时按 `blk` 挑，块号也对不上就不猜。
4. **多行块**：几行合成一段时定位得到，换成一行或三行后总行数对得上。
