# 推荐配装页

管 `builds/` 那一族：详情页、合集、索引页、填表页，以及它们查的词表。
改 `tools/convert-build.py`、`tools/vocab.py`、`tools/mods.py`、`builds/` 下任一文件，
或写 `references/builds/<赛季>/*.md` 源稿之前读这一份。

站点全局的机制与闸门在 `CLAUDE.md`，视觉规范在 `design.md`。


`builds/` 由 `tools/convert-build.py` 从 `references/builds/<赛季>/<slug>.md` 生成，**不手改**。

赛季走目录：`references/builds/s29-凯旋纪念碑/` 里的配装出到 `builds/s29/<slug>/`，
「凯旋纪念碑」直接落成面包屑与徽章文字，不另建「赛季名 → 拉丁 slug」的对应表。
当前赛季只有 `shell.SEASON` 一处定义：只有这一季进 `shell.pages()`，索引页、
全站搜索与外壳闸门因此只收它；旧赛季照常生成（外壳不与全站分叉），站内点不到，
手里已有链接的人仍打得开。换季改那一个字符串。

源稿只写名字，图标、链接与着色由词表查出来。所以这个生成器排在三个资料生成器
之后、`build-search.py` 之前。`tools/vocab.py` 扫已生成的产出建表（与 `build-search.py`
同理：产出结构统一，源稿要分三种方言且没有分节 id），槽位 → 允许的来源页写在
`vocab.SLOTS`：「全知之眼」既是异域护甲又是一把传说狙，源稿写在哪个键上就只查哪几页。
分支页的同名条目由源稿的「分支：」定优先：星相「地狱火」在烈日页与棱镜页各有一条。

分支定不下来的同名，在名字后面写分节括注挑一条：Bungie 在不同弹药档上复用枪名，
「隐士」既是冲锋枪也是融合步枪，「极高反射」既是手枪也是火箭手枪，源稿写
`传说武器：隐士（冲锋枪）`。括注只在整名查不到时才拆：站内自加的消歧后缀本身
就是名字的一部分（「故我在（电弧元素）」，词表里这样的有 25 个），见名就拆会把那条
正主弄丢。填表页由 `form.js` 的 `srcName()` 自动写出来，判据与 `vocab.pick` 同一条：
同名且来源页不同才算撞车。元素页上的同名不补括注：那一族由 `prefer` 挑，给棱镜
配装的「地狱火」写上「（星相）」反倒把它钉到烈日页去，括注在 `prefer` 之前收窄。
查不到即中止：错别字与站内改名因此暴露在构建时，而不是让页面上出现一个没图
没链接的格子。护甲模组按部位查（`kind`），套装按 2 件／4 件查。

### 版面

页面由六行面板组成，每一行拉满版心（1060px），行内的面板按 `--n`（自己的格数）分
份额。左右两缘因此在整页上落成两条垂直线，那是这一页的脊柱。`render()` 里 `row()`
出一行、`group()` 出一个面板，`--n` 同时是格子网格的列数与面板的行内份额，两者相等，
所以同一行里各面板的格子宽度自然一致。

| 分区 | 行 | 面板 |
|---|---|---|
| 职业 | A | `超能` · `技能`（手雷/近战/移动/职业技能）· `星相` |
| | B | `碎片` |
| 武器 | A | 每把枪一个 `.rig`（枪 + 它的 0–2 个 Perk） |
| 神器模组 | A | 一个面板，标题即神器名 |
| 护甲 | A | 异域护甲 · 套装 · 六维（`.stats-card`，三列两行） |
| | B | `头盔` `护臂` `胸甲` `腿部` `职业物品` 五列，每列三枚模组竖排 |

六维不自成一节，挂在护甲主角行的右端。异域加套装最多三格，那一行的后半截本来
是空的，六维六格摆成三列两行正好填上。

一格一行，图名值横排。图上名下的竖排要 73px 一格，两行下来比同一行里那两个格子
面板还高一截。两行摊满卡高（自动行在 `align-content: stretch` 下分掉剩余高度），上下缘
因此与那些 56px 图的格子齐平。

这张卡不给面板标题。同一行的异域与套装两个面板都没有标题，多一行「六维」会让六格
整体下沉、与旁边的格子对不齐；属性名每一格里已经写着。

宽度随内容（`flex: 0 0 auto`，三列 1fr 等宽取最宽那一列），行里不够时缩的是左边
那个格子面板：格子的 264px 是上限不是下限，缩下去只是变窄，换行会把主角行豁成两段。

护甲那五个部位是唯一列数不等于份额的地方：`cols=1`、三枚模组竖排，五列并排合起来
是一张 5×3 的矩阵，那是这一页的视觉重心。

面板标题只在它比上方的 `sect-label` 多说一件事时才写。武器行与护甲主角行不给标题。
上面已经写着「武器」「护甲」，再写一遍「武器与 Perk」「装备与套装」是噪声，格子形状
（56px 图的是主角，24px 图的是 Perk）自己说明身份。

主角行（`.slot-row.lead`）不拉满。它最多三格，拉满会让异域护甲一格宽到 500px；
格子封顶 264px、左对齐，右侧留白读作呼吸。

`.rig` 的 `--n` 按格子实际需要的宽度加权，不按格数（枪 16、Perk 10）：等分会让独占
一组的异域枪只拿到七分之一行宽，「英勇利刃」四个字折成两行。

格子里的名字折行时走 `text-wrap: balance`。加了起源特性的一组有四格，Perk 格窄到
放不下五个字，贪心折行会断成「赢弱能」加「量球」这种一头沉；balance 挑「最长那行
最短」的断点，四个字落成 2+2、六个字落成 3+3。格子够宽时它不生效，一行放得下就不折。

格子分两档，判据是这件东西是不是这一段的主角：

| 档 | 用于 | 形状 |
|---|---|---|
| 主角格 `.item.gun` `.gear` `.set` | 异域、传说武器、套装 | 图 56px 在左，名字 13px 在右 |
| 配料格 `.item` `.item.perk-cell` | 超能、技能、星相、碎片、护甲模组、神器模组、Perk | 图 32px（Perk 24px）在左，名字 11.5px 在右 |

图左名右横排，中文因此不折行。图上名下、格宽 82px 的旧排法会把「动能武器激涌」折成
两行。没有图的格子（`.item.plain`，移动手段）补一个图标位的左内边距，名字才与邻格
的名字对在同一条竖线上。

分支色驱动整页的 UI 强调色。生成器按源稿的「分支：」给 `<main>` 落一个 `b-<slug>`
类，`builds/style.css` 里六行把 `--accent` 覆盖成该元素色；区段那枚方块、焦点环、格子
悬停的左缘、索引页卡片的左缘都跟着走。`--accent` 是 `design.md` 写明「子页面覆盖这一个
即可换色」的槽位，六个元素页就是这么做的，**不新增任何渲染色**。类名不加限定（写
`.b-arc` 不写 `main.b-arc`）：配装页落在 `<main>` 上，索引页落在每张卡的 `<li>` 上，
一处定义两处生效。

### 护甲模组的变体

站内的护甲模组页把一个族收成一行（「虹吸」一行盖住 16 枚元素虹吸，「光能意志」
一行盖住五枚元素版），行上写的是这一族的机制与三档数值。配装要指到具体那一枚，
所以 `tools/mods.py --distill` 从官方物品表把变体名蒸馏进 `tools/mod-variants.json`，
`vocab.py` 把它们并进词表。现有 16 个族、87 个变体。

一行摆两条的表要连第二条一起扫。异域护甲页的异域职业物品那张表一行两条词条：
行标题一条，中间一格再一条（源稿写 `{spirit|噬星者之灵}`，整格只有这一个标记，
class 落在 `<td>` 上）。只认 `<th scope="row">` 会静默漏掉一半：36 条里只进来 18 条，
页面上照常显示，填表页却选不到，从产出上看不出来。`vocab.py` 的 `SPIRIT` 补这一道。

跳转仍落在复合那一行：说明、数值与能耗都写在那里，跳过去才有东西读；格子上把
行名写成副名（`电弧虹吸` 下面一行小字 `虹吸`），读者知道自己会落到哪一条上。

归族靠名字不靠人记：多数变体整段包含行名（电弧虹吸 ⊃ 虹吸），包含不到的两族写在
`PATTERN` 里各带一行依据（站内写「稳定瞄准」，官方把元素插在中间；站内写「回收利用」，
官方叫「元素回收器」）；名字里既没有行名、也套不上形状的逐条钉在 `ALIAS`，同样各带
一行依据。都归不进去的当场列出来，那是站内缺的条目，补不补由人定，脚本不猜。

游戏内已移除的变体在蒸馏时剔掉。官方物品表留着它们（manifest 不删历史条目），
但拿不到的东西列进填表页只会让人选出一份挂不上站的配装。判据都在 `gone()` 里：双元素虹吸（电弧/冰影双虹吸、
电弧/缚丝虹吸组合…五枚）按形状认：虹吸族里带斜杠的名字只有它们；三枚动能虹吸
（混乱／电荷／热量）套不上形状，逐条钉在 `GONE_NAMES` 里，「动能虹吸」本身还在。剔掉之后要顺手清孤儿图标：
`icons()` 只下不删，用不到的 `.webp` 留在目录里，按「产出与表比对」查出来再删。

变体图标从官方物品表的地址取回，`cwebp -q 82 -alpha_q 100 -resize 64`，按编码后内容的
md5 命名，与护甲模组页自己的图标同放 `armor-mods/icons/`：同族资产、同一规格
（64×64 WebP），两处引到同一枚图时自动是同一个文件。重跑 `--distill` 时地址没变就沿用
已下好的那一枚：文件名换一次，读者的浏览器缓存就白掉一份。

### 源稿格式

首行 `# 配装名`，其后是头部键（`推荐人`、`描述`、`更新`、`场景`、`定位`、`分支`、`类别`、`核心`），
正文七个分节：`审核意见`、`职业`、`武器`、`护甲`、`神器`、`六维`、`注解`。槽位一行一格，
留空就是整行删掉，不写占位符。

| 键 | 写法 |
|---|---|
| `推荐人：` | 一行一个人，`名字 \| 链接`，链接可省 |
| `核心：` | 本页配过的任一件东西，决定页首那枚 96px 的图。范围由 `page_items()` 一处定义，同名时主角在前（异域、传说枪、套装）：「全知之眼」既是异域护甲也是一把传说狙 |
| `分支：` | 六个分支之一，定同名条目优先查哪一页 |
| `类别：` | meta、强度、创意或 PVP，单选必填。索引页按它分大节，详情页的铭牌接成「职业 · 元素 · 类别」。与 `定位` 是两回事：定位说这套配装在队伍里干什么，类别说它为什么被推荐。PVP 是类别不是场景：一套 PVP 配装的取舍与 PVE 的强度、创意不可比，摊在「场景」里会让它跟突袭、地牢并排，按场景筛出来一堆用不上的。它的 `场景：` 与 `定位：` 因此可以留空值（那两张表列的是 PVE 的），空了那一栏整个不出 |
| `传说武器：` | `枪名 \| Perk、Perk`，Perk 不足两个就少写一个 |
| `异域护甲：` | 一件；两件只有异域职业物品那一种，两件都得是「…之灵」。它在页上占一格、两条上下并排：一件装备带两条异域词条，摊成两格会读成穿了两件异域 |
| `套装：` | `套装名 2 件 × 套装名 2 件`，或 `套装名 4 件`。件数落在格子上：2 件与 4 件是两条不同的效果，名字一样，不标出来分不出 |
| `头盔：`…`职业物品：` | 每个部位的模组，模组必须确实属于那个部位 |
| `神器：` | 用的是哪一件神器。神器模组页的 7 个分节就是 7 件神器，模组归属写在分节标题上。面板标题那枚图是神器本体的真图，查 `tools/artifacts.json` |
| `模组：` | 七个模组名，不写槽位。模组按所选神器限定：「电介质」在加密数据盘与废墟石板下各有一条，混进别件神器的模组当场中止 |
| `六维：` | 六格、用 `｜` 隔开，顺序钉死（生命、近战、手雷、超能、职业、武器），值当纯文本落。下限写成 `80+`，区间写成 `150～200`，不定就写 `~` |
| `移动：` | 位移技能，查 `tools/moves.json`。站内没有它的资料页（跳跃、滑翔、瞬移既不是护甲模组也不是星相），所以格子有图有名但不是链接；名字与图标由 `tools/mods.py --moves` 从官方物品表蒸馏，写错当场中止 |
| `## 注解` | 推荐人自己的话，走 `markup.inline(rich=True)`，与资料页正文同一套标记 |

审核意见走 `## 审核意见` 分节，排在头部键之后、`## 职业` 之前。它是站方对整套
配装的判词，落成详情页里页头与「职业」之间那条通栏，以及索引卡上简介之上那两行：
裁到两行，分段在卡上并成一行。**不做成头部键**：头部键的值只能占一行，而这一段
与注解一样想写多长写多长、能分段，空行分段与段内 `<br>` 由 `prose()` 一处出，
注解、合集介绍与它共用。合集写在合集头部那一层，整份一条，排在 `## 合集介绍` 之前。
那一节的正则贪到头部末尾。

只有审核台写得出来：填表页默认收着那一栏（`#f-verdict` 带 `hidden`），审核台把
填表页载进 iframe 之后调 `starsideForm.review(true)` 才立起来，投稿的人因此看不到它；
有值时它自己立起来，所以读者从详情页「复制配装」粘回工具里看得见。**不靠鉴权，
靠不给入口**。它不进 `SAME` 那五项指纹：那是「这是不是同一套配装」的判据，站方后来
加的话不该让审过一轮的稿子认不出自己那一份，因此改它也不必跑 `rekey`。散文与描述、
注解同路：走 `inline(rich=True)`，进 `items.py --builds` 自动着色，进 `check()` 的
着色闸门。

备选装备先写进注解（「黎明琢面可换使命琢面」），不做成槽位语法。等到三套以上
配装都在注解里写了备选，再看它普遍长什么样，那时画法自然就定了。

### 合集

一份源稿装 N 套可切换的配装，判据是头部的 `合集：是`，`# ` 分隔每一套；`split_set()`
是全脚本唯一认这个分隔符的地方。成员块内部就是单套配装的源稿，一字不改。
`blocks_of()` 与填表页的 `write()`／`importMd()` 都按块原样复用，所以加一个槽位只改一处。
`合集：是` 与第二个 `# ` 互为断言，缺一即中止：只按标记判，写了标记忘了写第二套会出一个
空合集；只按 `# ` 判，注解里手滑打出的一个 `# ` 会把半篇正文静默切成第二套。

它答的是「一个角色带着一组配装来回切」：进图用刷图那套、boss 房切单体、遇到盾切打盾。
游戏内能存 20 套，站上收到 12（`SET_MAX`）。一队人各穿一套打配合是同一个容器的另一种填法，
不另做东西。

键的归属：描述、定位、职业每套各写一份：描述与定位正是它们互相区分的地方，写在头部
就成了一排全选；推荐人、更新、类别、场景写在合集头部。场景与定位一样是筛选维度，
两者并起来落成卡片上那排标签 chip（`tag_values()` 按受控词表验值）。
合集头部不写 `核心：`：那枚图由各套的核心拼成一张马赛克（`core_mosaic()`，最多
四枚，`SET_TILES`）。再让人挑一个就是同一件事的第二个来源，而且它会随着某一套换装
变陈旧，源稿上还看不出来。一枚时就是那一枚、不套壳：只有一套核心的合集没有理由
长得与单套配装页不一样；两枚横排居中成一条带，三枚上二下一，四枚二乘二，全由
`flex-wrap` 加两向居中出，不按数目各写一套规则。尺寸由生成器写在 `--sz`／`--tile` 上：
页头 96、索引卡 64 两处共用同一段结构。那两条 CSS 要逐处指名（`.build-head .core
.core-mosaic img`）：外层给单枚图定的尺寸是 (0,2,1)，单类压不过，不指名整块会被拉回
96 而四枚图叠着溢出去。

产出与单套同一个命名空间（`builds/<赛季>/<slug>/`），所以 `shell.pages()` 的详情页那一段、
点赞、搜索、`sync.py` 的 `land()`／`sweep()`、云函数写死的三段 `_id` 正则全都不用改。
另出两页：`builds/sets/index.html` 与 `builds/new/set/index.html`，两条固定路径写在 `pages()` 里。

索引页两张共用 `render_index(sets=…)` 一份实现，逐层同形：类别分大节、职业分小节、
标签走筛选 chip，两页只差 `data-noun` 一个字。大节不改用场景：场景答的是「在什么
副本用」，那是筛选维度；类别答的是「这一份为什么被推荐」，那才是目录的分法，拿场景当
大节反倒让类别没地方显示。节内按职业分小节：`app.js` 的职业维度读的就是 `<ul>` 上面
那一级标题，换成别的分法那一维就废了；跨职业的合集站在 `MIXED`（多职业）那一格。

详情页默认逐套查看（左目录右配装），一枚按钮展开全部。N 套全部写进 HTML，收起 N−1 套由
`builds/set.js` 在加载时施加，与列组页、折线图页「默认隐藏不写进 HTML」同一条约定：无 JS
时它天然就是竖排，全部可读，`#set-3` 照旧跳得到。选中哪一套只认 hash，发出去的链接因此直达
那一套。视图开关落在左栏的头上、不做成 `.toolbar`：那一套由 `app.js` 建，而配装页不引它。
`content-visibility` 套在 `.set-one` 上而不是 `.set-wrap`，后者含着 sticky 的左栏。

复制按钮跟着每一套走（游戏里导入是一套一套的），`<pre class="src">` 一套一份，
装的是 `solo_src()` 补齐了继承键之后的完整单套源稿：不补的话粘进配装工具，推荐人与类别是空的。

云函数的 `fingerprint()` 只按头部算（`md.split(/\n# /)[0]`）。不切的话 `SAME` 里的
`^职业：` `^分支：` 全文扫，会静默抓到第一套成员的：调换前两套的顺序再投，指纹就变了、
顶不掉旧的，站上多出一份重复合集，点赞数跟着甩掉。单套只有一个 `# `，切了等于没切。
改了这一处要跑一次 `{a:"rekey",k:…}`。

审核台按 md 判要哪一页：单套与合集各留一个 iframe、切换时收起另一个（`stageFrame(kind)`），
改 `src` 就是整页重载，而那正是那个函数存在的理由。缺项逐套报（`missing()`），职业由成员
现算（`clsOf()`）。

### 闸门与索引

`check()` 查两件事。**结构**：该有的段都在、标记转干净了。配装页正文没有可比的连续
文本，全是查表补出来的图标与链接，逐字保真在这一页不成立，闸门是词表，每一个
名字都要查得到。**着色**：作者写的那两段散文（描述与注解）里，全站术语不许素着；
槽位那些名字由查表着色，不归源稿管。词表与 G6 同一份（`items.py` 的 `MECH` 减去
`LOOSE`），不在这里另立一份。

描述在这一页是正文（首页卡片与 `<meta>` 也用它），所以允许写着色标记：正文走
`inline()`，meta 与卡片用剥干净的那一份，不然标记会漏进 `<meta>`。

配装源稿进 `check_terms.py` 的中文正名与 token 两道，**不进 G6 正查**：配装正文几乎
全是物品名，正查会要求给每一个都套 `{token|}`，而它们本该由查表变成带图标的链接。

全站搜索一套配装只进一条记录，只收配装名：搜「元素虹吸」该命中神器模组页那一条
正主，而不是同时命中带了它的每一套配装。想被搜到就把词写进配装名里。

配装详情页的面包屑要写出 `parent_href`。它在 `builds/<赛季>/<slug>/` 下，索引在
`builds/`，隔着两级；`shell.nav()` 缺省的 `../index.html` 会指到 `builds/<赛季>/`，
那里没有页面。

索引页 `builds/index.html` 按类别分大节（meta、强度、创意、PVP），节内按职业分小节。
没有配装的类别不出大节（`render_index()` 里那句 `if not pool: continue`），所以加一个
类别就是 `markup.CATEGORIES` 加一个值，站上一个字都不变，等有人用了它自己出现。跳转
chip 对应大节（`data-chip-label` 写「类别」）；职业小节只是节内的 `h3.sub-label`，不占
chip：只有两个大节时跳转本来就不难，找职业直接在旁边搜索框输「术士」。

卡片是竖式的，一排六张：图在最上，往下是配装名、推荐人、简介、标签、时间与赞数。
简介固定三行、标签固定两行，都超出即裁。一排六张里有一张长出来，下一排的顶缘就是锯齿。
左缘那条 2px 亮边跟着该配装的分支色走。

筛选走工具条上的维度 chip（`.toolbar` 的 `data-facets`）：职业、分支、标签三行，
同行多选取并集、行间取交集，再与搜索框取交集。维度从卡片上现扫：职业是卡片上方那级
小标题、标签是卡里那几个 `<i>`。只有分支的中文名由生成器给（`<li data-branch>`），
DOM 里只有 `b-prismatic` 这个 slug，在 `app.js` 里再写一份 slug→中文 就是 `markup.BRANCH`
的第二份定义。类别不做成一行 chip：它就是页面的大节，跳转 chip 那一排写的正是这几个
字，同一排字出现两遍读者分不出哪一排管什么。

空掉的职业小标题与类别大节都由 `filter()` 收起，与横幅行同一段代码。小标题那一条
只能在 JS 里做：CSS 要写成 `.sub-label:has(+ .entries:not(:has(> li:not([hidden]))))`，
而 `:has()` 不许再套 `:has()`，那是一条无效选择器，写在样式表里既不报错也不生效，
所以从前那条「小标题自己隐藏」的规则一直没起过作用。

编辑台 `admin/` 不引这份样式表：它的配装列表是行式的，一屏要扫六七十条，卡片得滚
三屏。两处共用的只有六行 `.b-*`，那六行在 `assets/site.css`：配装页落在 `<main>` 上、
索引页落在每张卡的 `<li>` 上、编辑台落在每一行上，一处定义三处生效。

索引页的版心是 1500，不跟着配装页收到 1060：它是卡片目录，与首页的目录同形。同一份
样式表管三种页面，所以这一档写成 `body:has(.entries)`，不写在 `:root` 上。

### 悬停详情

指到一件装备，就地摆出它在站内那一页上的说明，配装详情页与填表页共用
`builds/tip.js`，实现只留一份。契约只有一条：格子上带 `data-d`，值是
「页面\t名字\t分节」：详情页由 `convert-build.py` 的 `item()` 写，填表页由
`form.js` 的 `fill()` 写，脚本本身因此不必认识行、槽位与词表。分节那一段解决同名
不同效果：「玻璃拱顶」的 2 件与 4 件是两条效果，名字一样。

说明另存 `builds/desc.js`，不进 `vocab.js`：1592 条合计 1020 KB（gzip 196 KB），
塞进词表会让配装工具一打开就下将近一兆。照 `assets/search.js` 那条约定：不进首屏，
`load` 之后空闲预取，第一次悬停再兜一次；取不到就不弹面板，填表照常。关掉开关连
预取都不做，状态记在 localStorage 的 `tipoff`，与点赞去重同一条约定。`desc.js`
路径由 `tip.js` 按自己的 `src` 现算，不由各页传进来。

它与 `search.js` 同理是页面文本的第二份副本，但在另一个文件里、不进任何页面的 HTML，
各生成器的逐字保真闸门因此照旧成立。

### 填表页

`builds/new/` 是给推荐人填的公开页：选完直接生成标准源稿，复制发过来即可挂站。
`builds/new/set/` 是它的合集版。

两页共用同一份 `form.js`，模式由 `#sheet` 上的 `data-set` 声明，与 `app.js` 从
`.toolbar` 的 `data-*` 读配置同一条约定；中间那块空槽版面逐字相同（`new_blocks()`），
合集那一页多出来的只有页顶那一层合集头部与左边那列目录。`pen` 是「一套配装」那一层的
范围：合集页顶另有一层输入位，`resetAll()` 与 `val()` 不能把它们一起清掉；单套页
`pen === sheet`，行为逐字不变。图标前缀从 `site.css` 那个 `<link>` 上现取：两页深浅
差一层，写死一个会让深的那页整页图标 404。

切换某一套就是「把当前这一套 `write()` 出来存进数组，`resetAll()`，再 `importMd()`
下一套」：`write()`／`importMd()`／`resetAll()` 三个函数原样复用，页面上永远只有一套配装
的 DOM，不引入第二套状态模型。「复制这一套」是默认动作：合集里各套重合度极高，空白新建
反而是第二选项；复制出来的那一套自动改名，否则目录上两行长得一样，点错了看不出来。
导入时逐套都导一遍再回到第一套：认不出的那几条要一次报全，等切过去才冒出来的话，
审的人以为这一份干净；顺带这一趟把每一套的核心图与合集那枚 96px 图都取到了。

合集页的版心是 1296，不是 1060（`body:has(.set-wrap)`）：左边多一列 208px 的目录，
配装那一列必须与单套页的行等宽（1016），否则职业那一节两条钉死的像素（286 与 562）
加上沟就有 868px，超能只剩它 18px 的 basis，整行塌掉。同一条也要求那三条按
`[id$="sec-1"]` 认、不按 `#sec-1`：合集详情页里一套一份分节，id 带前缀。

每一套各有自己的核心选择器，48px 见方摆在这一套名字的左边（`.one-core`），图仍
是 32：它决定左栏目录上那枚图，也是页顶那张马赛克的一块。那条规则要限定在
`.one-head` 里并带上 `.item`：选择器的候选格会复制目标格的 class，不限定时每一条
候选都被压成 48px 单列方格；不带 `.item` 则压不过 `button.item { width: 100% }`。
核心格的边长由格子自己用 `data-size` 声明，`syncCore()` 现读。

左栏目录每一行是三列：图 / 职业·元素 / 名字·定位。职业与元素单占中间那一列
（`.who`，上下两行）：挤进副名那一行时 208px 的目录只剩得下一个标签，定位整段被
省略号吃掉。名字与定位写 `grid-column: -2 / -1`，不写死列号：还没选核心的那一套没有
图，整行收成两列，最后一列两种情形都对。

移除一套的叉挂在目录每一行上，不做成「删掉当前这一套」的按钮：要删的多半不是
正在编辑的那一套，先切过去再删是多一步。加一套是列表下面一枚占满宽度的加号，
它是列表的延长，不是标题旁的控件。「复制这一套」挂在这一套页头的右端
（`.one-head` 的 `.head-acts`），与详情页那枚复制同一个位置。

页顶那两处与左栏目录都是镜子，与详情页逐段同形：96px 核心图、「职业 · N 套 · 类别」
那条铭牌（职业由各套现算，跨职业写 `MIXED`）、目录行那 32px 的图。成员铭牌末位写定位
（详情页那一页就是「猎人 · 棱镜 · 清怪」），单套那一页写类别，同一处 `tail()`。
核心那一格是 `<span>` 不是 `<button>`：合集的核心不给选择器，交互态因此自动没有，
`a.item` / `button.item` 才有 hover 与焦点环。

站内叫「配装工具」，名字只有 `FORM_NAME` 一处定义，首页卡片手写，要跟着改。
它不挂在推荐配装下面：面包屑写成 `Starside / 配装工具`：首页「攻略与工具」直接
进得来，读者不必先看过配装才来填一份。反向那条入口留着，在索引页标题右边。

这一页就是详情页的空槽版面，由 `render_new()` 用同一套 `row()`／`group()`／`glyph()`
出，类名与详情页完全一样；没填的槽位是一枚虚线空格，点开就地展开图标网格，选中即落成
带图标的成品格。填完了页面就是成品，**不另做一份预览**：两套 DOM 会让版面改一处得改
两遍。版面与候选范围写在 `slot_cell()` 的 `data-*` 上一处，`form.js` 现读，与 `app.js`
从 `.toolbar` 的 `data-*` 读配置同一条约定。

候选不写进 HTML：三千多条选项写进来就是把词表抄了第二份，由 `builds/vocab.js` 建。
`vocab.js` 与生成器查的是同一份词表，填表页列得出来的名字，生成器一定查得到。
一行六列 `[名字, 分节, 页面, 图标, 着色, 副名]`，尾部的空列剥掉；页面集合相同的槽位
共用一份列表：五个技能槽指向同一组元素页，存五遍就是把 316 行抄了五次。

按职业收窄时只挡「另外两个职业的」，不挡「不按职业分的」。异域护甲那一份列表里
除了三个职业各 55 件，还有 6 条通用词条与 3 件永劫教派的学派护甲；按「kind 不等于本
职业就丢」筛会把后面这九条整批藏掉，而 `vocab.pick` 明明查得到。判据写成「kind 是三个
职业之一，且不是本职业」。

候选按 `kind` 收窄，不按元素页收窄。棱镜把各子职业的技能拼在一起，一套棱镜配装的
超能可能来自烈日页、手雷来自电弧页，`vocab.pick` 的 `prefer` 是偏好不是限制。按页面
硬筛会把这些正确的选项藏掉，所以元素页那五个槽只把本分支的排在前面，收窄交给 `kind`
（超能技能 31 条、手雷技能 32 条、星相 60 条、碎片 99 条）。跟职业绑定的两个槽
（职业技能、异域护甲）另按所选职业筛。

`<button>` 的宽度是收缩到内容的，不像 `<a class="item">` 那样撑满格子。`button.item`
要写死 `width: 100%`，否则整页的空槽会缩成一列三十来像素宽的窄条。

候选排序四层：本分支那一页、元素或职业、族、名字。中文按
`localeCompare(…, 'zh-Hans')` 排，不按码位。中间那一层按槽位分两种：

- 跟职业绑定的槽位（职业技能、异域护甲）按猎人、泰坦、术士排。
- **其余**按元素页的站内次序（电弧、烈日、虚空、冰影、缚丝、棱镜），次序取
  `BRANCH` 的键序，不另定一个。一格手雷混着六个元素的三十几枚，按名字排会把
  同元素的拆散。

第三层的「族」是副名（电弧虹吸的副名是「虹吸」）：护甲模组一格里混着弹药生成、
抗性、稳定瞄准三四个族，不分组就交叉着摊开，扫读时对不上。

词表里有两类行不是能选进配装的东西，按槽位挡掉，不从词表里删。kind 为「分节」
的是分节标题：三个职业那三条正被「职业」那一格的选择器用着，删了那一格就空了；
「固有 Perk」写在职业技能页上，是职业的先天优势（猎人基础疾跑 8.5 米每秒），
不是可选的技能。挡法：槽位声明了 kind 就按 kind 收，没声明的一律排除「分节」
与 `SKIP_NAME`。

Perk 那两格只列「武器 PERK」。一把枪的两列可选 Perk 就是这一类；起源特性是另一条
线（随枪的出处走，一把枪固定一个），混在同一份候选里挑不出来，所以单给一格、默认
收起，按 ＋ 才出来。源稿格式不变：起源特性就是 `枪名 | Perk、Perk、起源特性` 的第三项。

格数会变的面板把上限出满，多的收起来，标题右边给控件。两种控件都落在 `<h3>` 里：

| 控件 | 用在 | 行为 |
|---|---|---|
| `data-add` | 技能面板的移动、每把传说枪的起源特性 | 默认收起，按钮叫出来；再按收回并清空 |
| `data-count` | 碎片，0–6 格，默认 5 | 加减可见格数，两端禁用按钮 |

按钮的 `data-add` 与格子的 `data-addable` 对上，**不按槽位名找**：起源特性与 Perk
同属一个槽位，只是 kind 不同。

格数一变就要改 `--n`（它同时是格子列数与行内份额），不然行内份额与实际格数对不上。
面板按露出来的格数算，rig 按格子的档次加权（枪 16、Perk 10），与生成器 `rig_of()`
同一套权重。收起的格子要一并清空：留着一个看不见的值，生成的源稿里会凭空多一项。

神器模组的选择器摆成神器盘：7 列 × 3 行。列是那件神器的七行，纵向是一/二/三级，
位置由词表的第七列 `pos`（`行,档`）给：`vocab.py` 扫神器模组页时按 `data-tier` 与序号
现算，不靠人记。挑的时候不必数，你在游戏里看见的就是这个形状；那一行小字也从分节名
（每行重复一遍的「废墟石板」）换成档位。搜出来的结果不摆：一次只剩两三条时，
21 格里空 18 格比排成一行更难看。DOM 次序按「先一级那一行，再二级、三级」排，与格子
摆出来的次序一致，回车选中的第一条就是眼睛看到的第一格。

七件神器走自己那份列表（`tools/artifacts.json`），带本体的真图；不从模组的分节名
反查：那样只得到七个名字，选择器里是七个素格子。

选择器一行恒为七格，与神器盘同宽：七件神器的模组盘就是七列，别处跟着它对齐，
一行几格因此不随容器宽度与候选条数变。格子约 138px，装不下的名字折两行，行高由
`min-height` 拉平，不让某一行忽然矮下去。

没选神器之前不列模组。七件神器各 21 枚，混在一起是 147 条；更要紧的是它们在神器盘
上的位置一件一套，七枚会叠在同一格。所以模组的选择器要求候选全来自同一件神器
（`bare(kind)` 相同）才摆成盘，没选神器时直接在计数位写「先选一件神器」。

职业、元素、核心三格自己就是选择器，页头不另设一排 chip。选中只改 `state`，
画由 `mirror()` 与 `syncCore()` 各自一处负责：元素那一格用的是分支页上「那个职业」
的分节图，换职业要跟着换，走 `fill()` 会把旧职业那枚图留在格子里。三格的候选各有
出处：职业走 `options('职业', '分节')`，元素走 `branches()`（当前职业在六个元素页上
的那六条，名字显示成分支名），核心走 `coreList()`（本页已经配好、且有图的每一件，
按页面次序去重）。核心跟着内容走：被选中的那件东西一清空，核心跟着落空，
`syncCore()` 每次重算源稿时对一遍，不留一枚指向空气的图。

选中「…之灵」时异域护甲那一格里冒出第二个槽，选别的异域时收回并清空。收放按
名字判，不给按钮，那是游戏规则不是版面偏好。第二个槽带 `data-only`，候选再按词尾
收一道，只列那 18 条词条。缩不缩由 CSS 的 `:has(> :nth-child(2):not([hidden]))` 判，
不另给一个类名：那第二个槽是自动收放的，类名要 JS 再同步一次，多一处会不同步的状态。

选了 4 件套自动补上同一套的 2 件。游戏里 4 件的效果包含 2 件那一条，所以两格
套装该同时立着。只补空的那一格：另一格已经有东西是填表人自己选的，不替他改；
生成源稿时 2 件排在 4 件前面。

六维与详情页同一张卡、同一个形状，值那一格是按钮。四个写法（不限／至少／指定／
区间，都是两个字，chip 排出来一样宽）加一到两个数值框摆进格子里要三倍宽，摆进选择器里格子就还是详情页
那个尺寸，与这一页别处「点空槽 → 就地展开选择器」同一套动作。写法表只在 `form.js`
定义一次（`STAT_MODES`），生成器只出空格子；值即源稿的记法：`~`、`80+`、`80`、
`150～200`，只填了下限就还不成一个区间，回落成 `~`。这一格的列宽写死 130px：值从
「~」变成「150～200」时列宽会跟着长，整条主角行跟着抖。

页头与详情页逐块同形。左列是核心那枚 96px 的图加推荐者，右列是配装名、铭牌、
描述与两栏标签，类名照详情页写（`.core` / `.by-label` / `.cls` / `.facets` / `.tags`），
版式因此由同一份规则管，不为填表页另写一套。铭牌那一行照着下面「职业」那两格显示，
本身不可点；两样没选全时写提示，不写半句：「术士 ·」读不出缺的是什么。
更新时间不给输入框：填表人写的日期只会是今天，那台机器自己知道（`today()`）。

适用环境与标签走受控 chip，不让人自由填。一套配装的适用环境与定位就那几种，
自由填会写出「宗师」「大师终极」「终极难度」三种说法，索引页筛不出来。预设写在
`convert-build.py` 的 `FACETS` 一处；多选的值汇到同一段里的隐藏 `input` 上，`data-key`
仍是源稿的键（`场景`、`定位`），`val()` 照旧按它读一个 `.value`，不另开取值路径。
标签框与详情页那些是同一条规则，选中只换字色与边框色、不换形状：同一排里选中与
没选中的框大小必须一样，否则每点一下整排都要重新对位。

预览是给 `#sheet` 加一个类，不另建一套 DOM。空槽、控件与源稿那两块收起来，
输入框脱掉边框与底色读作正文，整页点不动。按钮双向：预览 ↔ 退出预览。预览态下
那一排按钮改成固定在右下角：整页有一屏多，回到底部找按钮不成立。

导入前先复位。清空的不只是格子里的值：收起来的格子（移动、起源特性、异域职业
物品那第二条词条）要重新收回去，碎片的格数要回到默认。不复位会留下一个空着的格子
与停在上一份配装那个数的计数器。默认格数在初次渲染时记到 `.slot-count` 的 `data-n` 上。

从源稿导入：认得出的填上，认不出的整条跳过并报出来。一份源稿可能是上个赛季
写的，某件装备站内改了名或下了架，那时把能填的填上比整份拒掉有用；报出来的那几条
写清是哪一格的哪个名字，不然填的人不知道该去补哪里。`importMd()` 是 `write()` 的逆，
两处的顺序必须一致：**身份先定**（职业收窄跟职业绑定的两个槽的候选，分支定排序与
强调色），神器先于模组（「电介质」在两件神器下各有一条），**核心最后**（它必须是
上面已经填进去的某一件）。

填过东西再离开或刷新要先问一句。判据是「生成的源稿与刚打开时那一份不同」，
不另记一份脏标记：那是同一件事的第二个来源，改一处就会不同步。

校验不做进前端。星相与碎片的联动、模组能耗、六维配点都是每季会变的游戏规则，
写进前端等于把同一套规则写两遍；这一页负责好填，正确性由生成器的闸门兜底。

验证走一条等价关系：在填表页把现有那套配装逐格选一遍，`#out` 的内容与
`references/builds/` 里那一份**逐字相等**。断言页照《验证》第 3 条写在 scratchpad 里，
驱动走真实的选择器（点空槽 → 搜索框输入 → 点候选），不直接改内部状态。
