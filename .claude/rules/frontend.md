# 全站搜索与 app.js

管浏览器里跑的那两件：全站搜索索引，以及 `assets/app.js` 建的工具条、过滤、
分节高亮、列组开关、折线图与轮盘。
改 `assets/app.js` 或 `tools/build-search.py` 之前读这一份。

`assets/search.js` 由 `tools/build-search.py` 生成，**不手改**。
站点全局的机制与闸门在 `CLAUDE.md`，视觉规范在 `design.md`。

## 全站搜索

首页 `index.html` 的 `.hero-search` 是搜全站的入口；资料页工具条上那只只搜本页，两者互不影响。

索引 `assets/search.js` 由 `tools/build-search.py` 从已生成的页面现扫，不手改：改文案改源稿，
重跑 `npm run build`。扫产出而不是扫源稿：三个生成器的产出结构统一（`section[id]`、
`.gen tbody tr`、`.mod`、`.set`），一份实现覆盖全部页面；源稿那边要按生成器分三种方言处理，
且没有分节 id，链过去落不到位置。页面清单取 `shell.pages()`，与 `check_shell.py` 同一份，
新增一篇资料不必回来登记。

产出是一个 JS 文件而不是 JSON：双击打开的站点也要能搜，而 `file://` 下 `fetch` 取同目录的
文件会被 CORS 挡掉，`<script>` 不会。文件里就一句 `window.starsideIndex = [ … ]`，
一条记录一行：这份文件每改一次源稿就要重生成并入库，按行写让 git 存得下增量：

| 记录 | 字段 |
|---|---|
| 页面，每页一条 | `u` 路径、`t` 标题、`d` 描述 |
| 条目，每条一条 | `u` 路径、`a` 锚点、`l` 分节、`n` 名称、`x` 全文 |

索引是页面文本的第二份副本，但它在另一个文件里、不进任何页面的 HTML，
各生成器的逐字保真闸门因此照旧成立。

表格行逐格取再用空格接。产出里格与格之间没有空白，整行剥标签会把相邻两格粘成一个词「1最后遗愿」。格内的行内标签照旧粘着，那与页面上 `textContent` 的行为一致，
两处搜索的匹配范围因此相同。合并块的续行没有 `<th>`，名称沿用上一行的，
它们本来就属于同一个行标题。

折线图页的表不进索引（`.toolbar` 带 `data-chart`）：行里全是坐标点（`-100 0.000 0.000`），
搜出来读者也用不上，整页只留页面本身那一条。

`check()` 那一档的闸门写在脚本里：每页至少一个带 id 的分节，分节必须取得到标题，
模组与套装必须取得到名称，任一条不合即中止。

### 新增内容怎么进索引

什么都不必登记，跑 `npm run build` 即可。新增一行表格、一个模组、一整篇资料，
索引都从产出现扫；页面清单走 `shell.pages()`，新页面自己会出现在里面。

`check_shell.py` 钉住这一条：清单里的每个页面都得在 `assets/search.js` 里出现，
只跑了生成器、忘了跑 `build-search.py` 的那一次当场报出，不等读者搜不到才发现。
条目级的陈旧靠 `npm run build` 之后 `git status` 里 `assets/search.js` 的改动看出来。

### 站内链接落到行上

站内链接一律写成 `<页面>?q=<词>#<锚点>`，落地由目标页自己的搜索框接手过滤
（`app.js` 的 `filter()`），读者不必在一整节里自己找。三处生成：

| 来源 | 谁补的 |
|---|---|
| 全站搜索的命中项 | `app.js`，过滤词就是读者输入的那个 |
| 配装页的每一格 | `convert-build.py` 的 `item()`，过滤词取自词表 |
| 资料页正文里的站内链接 | `convert-doc.py` 的 `land()`，文字在目标页是行标题时才补 |

`land()` 从目标页的源稿现算锚点，不读产出：同一次构建里产出可能还是上一版，
锚点会指错分节。文字在目标页找不到同名行就原样留着（changelog 里那些指整页的链接
本来就该落页顶）。

两条落地约束，由 `vocab.check_landing()` 钉住，`npm run build` 时执行：

1. 过滤词必须在目标页滤得出条目。词在那一页一个字都不出现时，读者看到的是一张
   空页：比不过滤更糟，且 href 本身完全正常，从产出上查不出来。护甲模组的变体因此
   用复合行的名字当过滤词，「电弧虹吸」在那一页一次都不出现。
2. 分节标题那一类条目不带过滤词，只滚到分节：它们是分节不是行，拿去过滤会把整页
   行滤光。

没有搜索框的页面不加 `?q=`。判据按 `app.js` 的三档来（列组模式与折线图模式整块不
建搜索），**不能只看 `data-item`**：神器模组页用的是缺省选择器，工具条上一个 `data-*`
都没有，按那一条会被判成没有搜索框，147 个模组的链接整批丢掉过滤词。

### 点开一条命中之后

命中项的链接写成 `<页面>?q=<词>#<锚点>`。落到那一页由那一页自己的搜索框接手过滤
（`app.js` 的 `filter()`），所以索引不必知道条目落在页面里的哪一行，锚点给到分节即可；
没有搜索框的六个页面只滚到分节。先过滤再滚：defer 脚本在解析完成后、锚点定位前执行，
顺序天然是对的。

索引不进首屏，由 `app.js` 注入一个 `<script>` 取回。它 1334 KB（gzip 329 KB），
进首屏就把首页拖成全站最重的一页。取回的时机有两个：`load` 之后的
`requestIdleCallback` 预取，以及首次聚焦搜索框。前者让想搜的人不必等，后者兜住
空闲回调一直不来的情况。取不到时在计数位上报出来，不留一个搜不出东西的空框。

## assets/app.js

首页走 `.hero-search` 那一支：建全站搜索框与命中列表，其余分支一概不跑。资料页的工具条
（搜索框、跳转 chip）从 DOM 读取分节标题构建，**不在 HTML 里写任何源文本**：写了就等于页面出现源表格文本的第二份副本，保真自检立即报重复。

选择器由页面在 `.toolbar` 上用 `data-*` 声明，缺省是神器模组页那一套，所以那一页的 HTML 一个字不用改：

| 属性 | 缺省（神器模组页） | 护甲套装页 | 资料页（`导航：是`） |
|---|---|---|---|
| `data-section` | `.artifact` | `.cat` | `.block` |
| `data-item` | `.mod` | `.set` | `.gen tbody tr:not(.lane)` |
| `data-label` | `.art-head h2` | `.cat-head span` | `.sect-label` |
| `data-noun` | 模组 | 套装 | 条目 |
| `data-chip-label` | 神器 | 分类 | 分节 |

另有一个可选的 `data-chip-break`：值等于哪枚 chip 的文字，就在那枚之前插一个占满整行的空项，chip 从那里另起一行。源稿写「跳转分行：」，护甲模组页用它把五个部位与十一个副本分成两行。

切一屏内容的 chip 一律 `history.replaceState`，只有钻进详情才压栈。跳转 chip
（`assets/app.js`）、合集目录（`builds/set.js`）与编辑台那四枚标签（`admin/admin.js`）
都是在同一屏里换个位置，走原生的片段导航点一枚攒一格，点五枚就得按五下返回键才出得去
这一页。跳转 chip 拦下默认行为自己滚，`href` 原样留着供右键复制与中键新开。
`file://` 下 `replaceState` 抛 `SecurityError`，所以 hash 即状态的那一处（合集目录）
先试再拦，抛了就放行、退回原生导航；跳转 chip 的地址栏不同步不影响滚动，不必回退。
编辑台里配装详情那一格照旧 `pushState`：那才是钻进去一层，返回键该回到列表。

搜索按条目的 `textContent` 过滤，整行不命中隐藏行，整节不命中隐藏分节与其 chip。隐藏靠 `hidden` 属性，`site.css` 里一条 `[hidden] { display: none !important }` 兜住：条目本身是 grid / flex，组件规则又排在 `site.css` 之后，不加 `!important` 就得每个组件页重述一遍。神器模组页检索期间三档并排对照关系失效，清空即恢复。

`.toolbar` 带 `data-cols` 时走列组模式（武器框架页），搜索与分节 chip 整块不建：chip 文字取自表头的 `data-g`（属性值，不是正文，不进保真比对），开关落成一张内建样式表按列序下的 `display: none`。同一列要下两条规则：合并行没有 `<th>`，序号整体前移一位，只下一条会让合并行错位隐藏。`data-solo` 里的组一次只开一组。

`.toolbar` 带 `data-facets` 时多出几行维度 chip（配装索引页）：搜索与跳转 chip
照旧建，下面按维度各加一行。维度从条目上现扫，不写进 HTML：写了就是同一份文本的
第二个来源。同行多选取并集、行间取交集，再与搜索框取交集；`filter()` 里那句命中判断
因此接上一个 `facetPass(i)`，隐藏与空节收起全都复用现成的那几段。

`.toolbar` 带 `data-chart` 时走折线图模式（压光伤害页），同样不建搜索与分节 chip：从 `.gen` 表现读数据画 SVG，画完由 `tuck()` 收起源表（见《资料文档页》那一条）。横轴恒为源稿给的全区间，不做缩放开关；工具条上只有一枚预设标注的开关，图例本身兼作每条曲线的显隐开关。坐标系固定 1000×580，SVG 用 `width: 100%` + `height: auto` 等比缩放，指针的屏幕横坐标与数据横坐标之间因此只差一个常数比例，换算不必读 viewBox。读数框必须 `pointer-events: none`：它跟着指针走，能接事件就等于每帧给 SVG 发一次 `pointerleave`，读数闪成一片。
