# 装备库

目录是 `weapons/`，页面叫「装备库」。全部武器与异域护甲一页查：DIM 语法的查询框、
卡片墙与列表、结果栏 + 详情。详情里配词条实时算属性，两位作者的推荐画成词条图标
外圈的光圈。交互对齐 destiny.report。

这一页**不写任何数据**。`tools/build-weapons.py` 只读实体层（`resolve.Facts()`
与 `rows.py` 的异域取法），产出 `weapons/` 下四个文件；`weapons/app.js` 与
`weapons/style.css` 是手写的。例外有四处，都是「那边已经有了，抄过来两处会各改各的」：
弹药块拾取量现读弹药生成机制页的表（见《框架数值》），护甲套装效果的图现读护甲套装页
的索引，神器模组的名字、归属与说明现读神器模组页的索引（见《神器模组》），配装卡与它的
样式现读配装推荐页的产出（见《用过它的配装》）。

## 产出

| 文件 | 何时载 | 内容 | gzip |
|---|---|---|---|
| `index.js` → `window.WPN` | 首屏 `defer` | 词表 `v` + 武器行 `w` + 护甲行 `a` | 134 KB |
| `pool.js` → `window.WPN_POOL` | 首屏画完空闲时取；查询或详情先用到就立刻取 | 属性表、属性组曲线、插件字典、词条栏、大师杰作、模组、神器模组 | 175 KB |
| `text.js` → `window.WPN_TEXT` | pool 之后 | 描述、Bungie 说明、站内实测、作者评语、异域站内详情、神器模组说明 | 342 KB |
| `index.html` | — | 外壳（`shell.head/nav/foot`）+ 空容器 `section#find` + 类型小图标 sprite | — |

插件在载荷里记下标，下标表 `pool.p` 每条带 hash；地址栏里写的是 hash，配置因此跨
构建有效。重复的东西进去重表只存一份：词条栏的格表 `L`、大师杰作选项 `M`、模组表
`D`、专属神器模组表 `AM`、站内实测 `H`、描述 `FL`、水印 `v.wm`。属性一律记 `pool.s` 的下标。

### 行的字段

武器行 `w[i]`：`hash, 名字, itemSubType, 元素, 弹药, 槽位下标, 勇士, 赛季, tierType,
标志位, 图标, 水印下标, 框架下标, 来源下标, 评级, 同组代表行, 同族下标`。标志位：
1 专家、2 全息、4 可锻造、8 可升阶、16 有大师杰作插槽、32 可强化、64 复刻。

护甲行 `a[i]`：`hash, 名字, 部位下标, 职业, 赛季, 图标, 水印下标, 异域 Perk 名,
LGpig 定位, 来源下标, 同组代表行, 同族下标`。

`pool.w[i]` 与武器行一一对应：`属性组, 基础投资值（按属性组的行排，没有这一项写 null）,
词条栏 [[栏名下标, 角色, 格表下标]…], 作者推荐 [[插件, 位]…], 可升阶, Aegis 推荐的
大师杰作 [属性名…], 大师杰作选项表, 模组表, 催化剂, 框架行下标, 专属神器模组表下标`。字段改了两侧一起改：
`build-weapons.py` 的 `build()` 末尾那段编码，`app.js` 顶上那几行下标常量。

## 护甲套装效果

第三个范围（`s=sets`）：56 套，一套两条效果（2 件与 4 件）。行 `t[i]` 是
`hash（set:…）, 名字, 英文名, 来源, 类型, 赛季, 标签, [[效果名, 件数, 图]…]`；详情
正文在 `text.st[i]`，每条效果带实测、Bungie 说明与作者评语。

**来源与类型是 Compendium 的两列**：一列写活动名（发射基地），一列写活动种类
（熔炉竞技场行动），56 套各写其一（39 : 17），所以卡片与列表都取
`来源 || 类型`（`setSrc()` 一处），`is:` 与 `source:` 两列都收。

卡片上两条效果各占一行（图、件数、效果名），**不把两枚图摞成名字左边那一块**：
一套的主角是这两条效果，摞起来会读成「一件装备的两枚图标」。

效果的实测与评语写在那枚 SandboxPerk 身上；**评语的键是 Compendium 的中文列名**
（`应用场景`、`获取地点`），与武器那一侧的 `explanation_N` 不是一套，所以另走
`set_author()`，不走 `one_author_block()`。

图取护甲套装页那一份（`armor-sets/icons/NNN.png`，序号命名）：官方图没拉进站内
图库，而那一页早就有。与弹药块拾取量同一类例外——这一页除此之外不读任何页面产出。

## 用过它的配装

详情最底下一块，摆的就是**配装推荐页那张卡**：整段 HTML 由 `build_cards()` 从
`builds/index.html` 与 `builds/sets/index.html` 现取（与 `build-home.py` 取首页预览
同一条），样式由 `card_css()` 从 `builds/style.css` 里按 `CARD_SEL` 取出来内联进页壳。
强度光环、审核意见、合集的马赛克与「3 套」角标因此原样都在，这一页一条都不重画；
配装页改一处，这一页跟着变。赞数那一枚在这里是死的：它由配装页自己的脚本填。

**按主键收**（`builds_by_key()`）：配装源稿的槽位值写成「名字#主键」，按名字收会把
同名不同物（故我在的狼群弹药与加拉尔号角的那一条）的配装混成一堆。卡片整段只存
一份、主键那一侧记下标：819 枚主键平均各指着 4 张卡，直接存要多 33 KB gzip。
排序按强度 meta > 强力 > 创意，同档按更新时间倒序。

版面上只改三样（`.entries.used-builds`）：一行三张、说明压到两行、核心图 52px。
**选择器要带 `.entries`**：卡片样式内联在页壳里，排在这份表之后，同权重时它胜出。

## 神器模组

详情里「大师杰作与模组」上面一块「可用神器模组」：这把枪用得上的神器模组。专属的按神器分行，同一枚
挂在几件神器上（群敌飞梭在好奇之器、废墟石板与女王兰香炉上是同一个 hash）就几行都列；
通用的放在末一行，每把枪都一样。标题旁的数是能用的模组枚数（专属加通用，挂在几件神器上
的只算一次）。模组悬停出站内实测，点开是神器模组页上那件神器的一节。

适用范围写在模组记录上的 `site_weapons`（70 枚，都在 `inventory-items.json`）：写了的
键全要对上才算能用，极寒凝视写着冰影与精准，冰影刀剑不算；一个键写几个值是其一即可
（远距填装：狙击枪或弓）。`{}` 是通用：任何武器都触发得了（「武器击杀」那一类），
「虚空武器击杀」这种写 `defaultDamageType`。

| 键 | 取武器记录上的 | 例 |
|---|---|---|
| `itemSubType` | 枪型 | 远距填装 `[12, 31]` |
| `defaultDamageType` | 元素，1 动能 2 电弧 3 烈日 4 虚空 6 冰影 7 缚丝 | 元素眩晕 `[2, 3, 4, 6, 7]` |
| `tierType` | 稀有度 | 永恒毁灭 `[2, 3, 4, 5]`：非异域火箭发射器 |
| `archetype` | `derived.archetype`，写框架 hash、按名字比：「微型导弹框架」库里有 7 枚 hash | 能量加速 |
| `precision` | 枪型打得出精准 | 精准平等 `true` |

打不打得出精准按武器框架页的精准倍率认（`precise_types()`）：火箭发射器、融合步枪、
刀剑、榴弹发射器、偃月五类整列留空。同一枪型有的行写了、有的行空着即中止。枪型能打、
这一把不能的，在武器记录上写 `site_precision: false`：异星噬菌与牵引器火炮打的是爆炸弹。认不出的键、
写了 `site_weapons` 却不在神器模组页上的记录都当场中止。

名字、图标、归属（神器与档位）与说明现读神器模组页的索引（`artifact_mods()`）：记录上的
`site_artifact` 只记得一件神器；图标由那一页源稿的「图标」行定，可以与记录上的官方图
不同；说明用那一页渲染好的一份，那一页不开富文本。页脚的更新时间因此也算上那一页。专属那几枚
逐把求值，结果去重进 `pool.AM`，`pool.w[i]` 记下标；模组表 `pool.am` 一枚一行
`[名字, 图标, [[神器下标, 档位]…], 通用]`，神器表 `pool.an` 是 `[名字, 锚点]`，说明在
`text.amd`（`text.H` 的下标）。

## 分组、版本与排序

一张卡是一组：键是（名字，赛季），专家版去掉末尾的括注再比。组里挑非专家非全息、
格子最多的那一把当代表，其次有收藏条目的，其次 `index` 最大的。作者评语按组合并。
「全部版本」是同名跨赛季的一族，新赛季在前。

开屏按评级排：Aegis S…F 与 LGpig T0、T0.5、T1… 折成同一把尺，取两家里更好的那一档，
一格写了几段的取最好那段；同档异域在前，其次按作者数、枪型、赛季新旧、名字。没评级的沉底。护甲
按职业、部位、赛季新旧、名字排。

## 词条栏与强化版

栏取 `Facts.pool()`，去掉固有（它画在「框架／异域特性」那一块）与异域的催化剂空壳。
栏名在 `LABEL`，按插槽类型白名单首项认：特征栏写 Perk 1／Perk 2，起源栏写起源特性，
其余用 Bungie 给这类插件的类型名。**认不出的类型当场中止**，补进 `LABEL`。

同一栏内按「同物」并格：名字取 `sameAs` 目标的名字，类型名以「强化」开头、或组内
同时有 tier 2 与 tier 3 时的 tier 3 是强化版。**有强化版的格只画强化版**，没有的
画基础版，不给切换。强化版找不到基础版即中止（`self_check`）。模组不走这条：
「强化稳定性」是一枚独立的模组，模组只按名字去重。

强化版照 DIM 画：圆内底边往上的金渐变、左缘一道金竖条、左侧一枚朝上的金箭头。
金是 `--c-enh`，取 `--c-stack` 的值：游戏里的强化金 `#eade8b` 与它 ΔE 10.9，按
design.md 一节读作同一个颜色。

## 作者推荐

Aegis 写在枪管、弹匣、Perk 1、Perk 2、起源五栏，LGpig 写在 Perk 1、Perk 2。名字走
`resolve.perk_key()`，按这把枪自己的池查。落不到池里的名字记数，基线
`MARK_MISS_BASELINE` 只许降：多一条就是源稿写了库里查不到的名字，读者看来是错的
改源稿，只是简称的进 `resolve.PERK_ALIAS`。

页面上 LGpig 一律写「小棒猪」（`app.js` 的 `AUTHOR`），数据里的键仍是 `LGpig`。

推荐画成图标外 3px 的一圈光圈：Aegis `--c-aegis`、小棒猪 `--c-lgpig`（头像小猪的
耳朵粉），两位都推荐是 `--halo-both`，六个元素色绕一圈。选中态是图标自己的边框，
与光圈分两层。Aegis 推荐的大师杰作在详情里**自动装上**，插槽画方形光圈；没有推荐的
插槽空着。Aegis 那一格可以写几枚（「填装\\操控性」说的是两枚都行），`pool.w[i][5]`
因此是一份名单：缺省装上第一枚，名单里的每一枚都画光圈。作者评语一位一块，左缘用他那一支光圈色。

## 属性

公式只有一套，`tools/facts.py` 的 `shown()`；`app.js` 的 `bankers()`、`interp()`、
`shown()` 是它的逐行翻译：不加默认插件；先按 `maximumValue` 截断再插值；两端截断
不外推；银行家舍入。`check_quality.py` 的 `WeaponPage` 把这三个函数原样抠出来，
全部武器 ×（基础、基础 + 各栏每一枚插件、基础 + 10+T）共两万一千格逐值比。

一个配置的属性按阶段累加，每一段画一截：枪管与弹匣、Perk（含模组与催化剂）、大师杰作、
T 级。条件生效（`isConditionallyActive`）的不进数值，只描一截边框。

### 大师杰作与 T 级是两件事

算法照 destiny.report：

| | 大师杰作 | T 级 |
|---|---|---|
| 可升阶的枪 | 选中属性 +10 | 装着大师杰作时，那枚插件列出的每一项 +T（选中属性也在其中），T1–T5，缺省 T5 |
| 旧枪 | 1–9 级给选中属性加它自己的数；满级取插件本身；专家版满级时其余 +3 | 没有 |

同一属性的大师杰作在池里有三种：条件项全为 0 的那枚（可升阶的枪用它）、条件项 +3
的那枚（专家版）、1–9 阶各一枚。等级按插件自己的数值认，不按名字：「5阶：冲击」
实际是 +4。冲击只给剑（类目 54），弓不给充能时间（类目 3317538576）。

「可升阶」按插槽认：带阶级外观、阶级击杀特效或阶级升级插槽（`TIER_KINDS`）。与
destiny.report 的 `isTiered` 逐把比，751 把对上 749，差「最终恐惧」及其专家版。
`derived.tierable` 另算进了锻造等级插槽，是另一件事，这里不用。

destiny.report 另给锻造武器加一份强化固有特性的 +2，实体层里武器与它的强化固有
插件之间没有连线，这一页不算。

## 框架数值

详情右栏在「属性」之后画一块「框架数值」：武器框架页那一行的评级、清怪／首领分数、
瞄准衰减射程、精准倍率、真实射速、基础填装、单弹匣红血／首领 DPS、红血／首领单弹药盒，
再加这一类枪的弹药块拾取量。精准倍率在打不出精准的五类枪上留空，那一行不画。

行取自记录上的 `site_frameStats`，键是 **(框架名, 枪型, 弹药) 三元组**，不是框架主键：
同名框架在库里有好几枚 hash（「精密框架」既是 `1636108362` 也是 `1322370662`），表行
只挂在其中一枚上，按 hash 配只覆盖 1494 把、按三元组覆盖 2032 把。弹药那一位是为
「动态热量武器 + 手炮」那两行来的：一行主武器、一行特殊弹药（无礼言论），去掉它键就
不唯一。取法在 `rows.frame_row()`，93 行去重后进 `pool.fr2`，`pool.w[i]` 记下标。
配不上的 176 把（146 把异域自带框架 + 30 把传说）整块不画。

弹药块拾取量现读 `references/docs/ammo.md` 的「弹药块拾取量」表（`brick_table()`），
键是 (枪型, 弹药)，进 `pool.brick`。行名与枚举的对应写在 `BRICK_ROWS`：火箭手枪是装
特殊弹药的手枪，火箭脉冲是装特殊弹药的脉冲步枪，重型弩箭是装威能弹药的战斗弓箭；
对不上的行当场中止。四个数画成「常规[带回收利用] 强化[带回收利用]」。

评级那枚字母徽标引 `--g-1`…`--g-8`，与色阶表、武器框架页的字母分级同一条弧，
八个色值只在 `site.css` 的 `:root` 里定义一份。

## 查询

语法照 DIM：关键字英文、值写中文；空格是且，`or` 是或，`-` 或 `not` 是排除，括号
分组。全角冒号与括号按半角认。未知关键字当裸词，悬空的 `or` 与不配对的括号忽略。

| 关键字 | 查什么 | 要哪份数据 |
|---|---|---|
| 裸词 | 名字、英文名、类型、框架、来源、词条名、描述；恰好是一个 `is:` 的值（`虚空`、`手炮`）时按 `is:` 算，加引号照字面搜 | 有什么先搜什么，数据到了重搜 |
| `is:` | 类型、元素、槽位（主手／副手／威能）、弹药（主武器／特殊／威能）、稀有度、勇士、标志（可锻造、可强化、可升阶、专家、全息、复刻、已钉选）；护甲是职业、部位。值也认英文，见下 | index |
| `name:` `frame:` `season:` `source:` `breaker:` | 名字、框架、赛季（可比较）、来源、勇士 | index |
| `perk:` `perk1:` `perk2:` `perkname:` `origintrait:` | 词条名（`perk:` 还查说明） | pool |
| `stat:射程:>=60` | 缺省配置（固定栏选上、不装大师杰作）的显示值 | pool |
| `perktext:` | 词条说明 | text |

`is:` 的英文写法不计大小写、空格与连字符（`is:HandCannon`、`is:hand-cannon`、
`is:"Hand Cannon"` 都是手炮），落到中文那个值上，药丸、预选行与补全都按中文值认。枪型
与部位取 manifest 的英文类型名（`is_aliases()` 现取，职业物品三个职业各一个名字）；元素、
弹药、稀有度、勇士、槽位与职业用 Bungie 的叫法，写在 `IS_EN`／`IS_EN_ARMOR`；标志的英文名
在 `app.js` 的 `FLAG_EN`。槽位不写 `kinetic`：那是元素，主手写 `kineticslot`。两张表都
不带原型：普通对象上 `is:toString` 会取到 Object 原型上的函数，整库都算命中。

槽位取物品自己的 `bucketTypeHash`。要 pool 的条件在 pool 到之前显示虚线药丸与骨架
卡片，到了自动重跑。补全按「去掉正在写的这一段之后的结果」计数。细分行只列多于
10 把、又不是全部的值，与 destiny.report 同一条。来源取 Aegis 写的 > LGpig 写的 >
manifest 收藏条目那一句。

## 版面

design.md 的约束之外，本页定的几条：

- 强调色退回骨白（`--accent: var(--bone-hi)`）：页面满是元素色，站点缺省的青色焦点环
  会被读成电弧。
- 属性条按来源分段只换明度；大师杰作与 T 级那两截走强化金，T 级用同色竖纹分开；
  负值走斜纹。图例每行三项，在属性栏里居中。
- 大师杰作与模组是两个方形插槽，悬停出说明，点开出选择框；T 级是插槽旁一排开关。
- 有大师杰作插槽的枪，图标底边画一片金光（`.gun.mw::after`，颜色取 Bungie 的
  masterwork-overlay）。那张官方图最底一行不透明度只有 32%，64px 下看不出来。
- 描述写在名字下面；事实 chip（含来源）在属性上方，点一下把那一条加进查询。
- 不做窄屏适配。

类型与弹药的小图标在 `tools/type-icons.json`，取自 justrealmilk/destiny-icons（CC0），
`build-weapons.py` 内联成页内 sprite；`app.js` 的 `glyph()` 引用时带上 symbol 的
viewBox，不带的话外层 svg 按 300px 宽算。
