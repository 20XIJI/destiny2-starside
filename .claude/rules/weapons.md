# 武器库

一把枪一页：词条池可配、数值随配置实时算、悬停出增量与结果值，三位作者的推荐
直接标在词条图标上。版面照 destiny.report。

这一页**不新写任何数据**。它按主键把事实层与人写层合起来显示：改源稿这一页跟着变。

## 数据在哪

```
data/facts/items.json        名字、类型、元素、弹药、勇士、发布版本、数值基线（inv）
data/facts/perk-pools.json   一把枪的栏位：固有、随机词条、可选模组、大师杰作
data/facts/stat-groups.json  属性插值曲线，79 组
references/items/*.json      人写层，三卷，由 tools/entities.py 从九张资料页抽出
data/icons.json              主键 → 官方图文件名
```

产出四份：

```
weapons/data.js    索引，2208 把枪。首屏要下，90 KB gz
weapons/plugs.js   全站共享的词条字典与插值表。**不挂在首屏**，空闲预取
weapons/w/*.json   一把一份，只存列结构与下标，点到才取。平均 0.8 KB
weapons/index.html 只有外壳与一个空容器
```

`weapons/app.js` 与 `weapons/style.css` 是手写的，不由生成器产出。

## 属性怎么算

这是这一页唯一「算错了页面照样好看」的地方。公式在 `build-weapons.py` 的 `show()`
与 `weapons/app.js` 的 `shown()`，两侧各一份：

```
base = Σ item.investmentStats        # 不加任何默认插件
v    = min(base, scaledStat.maximumValue)
显示值 = 银行家舍入(分段线性(v, displayInterpolation))
```

四个细节缺一不可，各有实测：

1. **不加默认插件**。加上 `singleInitialItemHash` 那批，还原率从 99.7% 掉到 74.9%。
   所以固有与固定的起源特性那两栏不参与计算（`c` 的第三位标着）。
2. **先按上限截断再插值**。不截断，后坐方向那一批整批错。
3. **两端截断不外推**。霰弹枪的伤害曲线从 `[10, 65]` 起，投资值 0 显示 65 不是 64.58。
4. **银行家舍入**。改成四舍五入，2208 把里 47 把对不上。

**不许在显示值上直接加插件的加成**：58052 个 (枪, 插件, 属性) 组合里 12.02% 会算错，
最差一处差 250（随机变量装相位弹匣，正确 600、偷懒 850）。

投资值里带第三位的是 `isConditionallyActive`（亡命之徒击杀后才加填装），
**不计入属性条**，只在悬停浮层里标一句「条件生效」。

三道自检钉着它：`build-weapons.self_check()` 每次构建都逐格对一遍 manifest 自己写的
显示值；`tools/check_quality.cjs` 里三条测试把 `weapons/app.js` 的那三个函数原样抠出来
再对一遍，管的是两侧会不会走散。

## 勇士克制按框架的 SandboxPerk 推，不读 breakerType

全 manifest 只有 18 条 `breakerType` 非 0。真正的编码是：

```
breaker = item.breakerType != 0 ? 它
        : 固有框架插件 perks[] 里那 19 个私有区码位 SandboxPerk
           屏障 → 1 贯穿护盾    过载 → 2 干扰    势不可挡 → 3 眩晕
```

覆盖 2207/2208。站内另有两处写法当**反查样本**，不当真相：
`references/docs/weapon-frames.md` 的「勇士」列（按框架，1539 把对得上，差 1）与
两位作者的「勇士」列（896 把，差 6）。基线在 `BASELINE`，只许降不许升。

## 赛季查表，不能算

`rel`（`releases.*` 去前缀）→ 赛季号是 41 项硬编码表，覆盖 901/906。版本号跳跃不规则
（420→450、540→600、820→900），v500 起资料片本体与它的首季共用一个赛季。
脏桶只有 `v400.season`：活动武器全塞在这一个 traitId 里，横跨六季，判不出就不写赛季。

**不要抄 DIM 的 `watermark-to-season.json`**：它停在第 28 季，会把第 29 季的 370 件
错标成 28。交叉验证过的部分（S1–S28，1745 件）与我们这张表逐条相同。

Aegis 的「赛季」列是**另一个量**——「现在还能在第几季的池子里刷到」，与首发赛季只有
61.7% 一致。chip 上两个数并存，别合并。

## 强化版合成一枚

全站五万个格子里两万八是普通版与强化版的重复：同名同图，说明差一句，数值差 1~2 点。
合并判据是同一栏内同名、一边 `tierType 2` 一边 `tierType 3`。

manifest 里**没有任何字段**把两版连起来。名字不同的两对写死在 `ENH_PAIR`
（身陷重围 ← 腹背受敌、强化黄金三角 ← 黄金三角）。名字相同、四个字段全一样的重复
（丢弃型弹匣、震荡榴弹）走 `merge()` 里按 (名字, 图标, 说明, 品阶) 的去重。

属性**默认按强化版算**，悬停浮层里两版都列。

## 加一栏可选模组或大师工作

`facts.py` 的 `KEEP_CATS` 收三个 socket 类目，`GEAR_KINDS` 决定「武器模组」那一类里
留哪几组。现在只留可选模组与「大师杰作：属性」那 14 种；`1–9 阶：XX` 那 126 个、
锻造与装备阶级两组、外观与击杀记录器都不留。

新加的栏必须带 `gear` 这一位。`resolve.weapon_pool()` 与 `Facts.pool_names()` 按它跳过
那几栏——前者拿来给资料页的词条名戳主键，后者拿来给复刻武器消歧，把「备用弹匣」
「大师杰作：射程」并进去，两件事都会错，而且会撞上逐字保真闸门。

## 图标的范围是事实层的全部武器

`icons.py` 的 `wanted()` 除了按页面索引扫，还单独扫一遍事实层里 `ty == 3` 的全部
条目：**每把枪自己那一张**（左栏每行与「别的版本」都要画），加上它各栏插件的图
（含可选模组与大师杰作）。这一页列的是 2208 把，其中一千多把不在任何资料页上有行，
只有这一条路能把它们的图带进来。

加一批武器或加一栏插件之后跑 `python3 tools/icons.py` 看缺多少，`--pull` 补齐。
`--pull` 只补不覆盖。

## 作者推荐落在图标上

能落到插件上的是 8 个列：Aegis 的 枪管 / 弹匣 / Perk 1 / Perk 2 / 起源特性，
LGpig 的 Perk 三号位 / 四号位。**Compendium 的「异域 PERK」列不落图标**——
那是异域唯一的固有 Perk，不是「十几个里挑两个」，同一个记号会把「唯一」读成「推荐」。

解析走 `resolve.perk_key()`，不另写一份。名字对不上时分两条路，判据是
**「这个写法对读者是错的，还是只对库里的键是错的」**：
前者改源稿（进 `check_terms.TERMS` 的禁用写法，跑 `items.py --normalize`），
后者进 `resolve.PERK_ALIAS`（不稳定弹药、斩首、自填这类通行简称）。

复刻让同一把枪有好几个版本，源稿那一行戳的常常不是作者写推荐时的那一版。
`relocate()` 按「哪一版能开出的推荐词条最多」把人写记录挪过去，现在挪了 105 条。

## 一枚 48px 圆图标上的五层状态

各占各的位置，互不抢：

| 层 | 记号 |
|---|---|
| 选中 | `--accent` 外环（`box-shadow`） |
| 悬停 | 边框转亮 |
| 焦点 | `outline`，留给无障碍 |
| 作者推荐 | **右上角首字角标** Ⓐ = Aegis、Ⓛ = LGpig，两家都推就并排两枚 |
| 有强化版 | **圆内左缘**一个朝上的箭头 |

强化版那个记号**走骨白不走金**：金在站内已经归异域装备所有，再给强化版一份，
「颜色即编码」当场失效。属性条同理，按来源分段只换明度不换色相，负值段走斜纹。

## 悬停分两层

悬停**词条**出的是「这一枚值多少」：名字、说明、逐项增量，有强化版就把两版都列。
悬停**属性行**出的是「这一项由哪几件东西凑成」：基础 / 各插件 / 合计。
两个问题不同，都要。属性条上另有 `▲结果值` 与主条下方一条 2px 的增量条。
